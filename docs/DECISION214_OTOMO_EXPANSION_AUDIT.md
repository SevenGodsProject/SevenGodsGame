## 3. シミュレーション（scratchpad・実装なし）

方式：既存の構え hook をメモリ上で差し替え、`START_GAME → PLAY_CARD/END_ROUND` を実 engine で回す。方策は決定213 と同じ定義（reader＝予告を無視／heal＝回復優先＝最良の代替／aware＝予告に対応）。ふつう・推奨デッキ・200〜600 試合／条件。

| 候補 | 内容 | 結果 |
| --- | --- | --- |
| **C 大技読み（完全受け切り→次ラウンド攻撃+3）** | 予告合計 ≥ 10（内部）を完全に受け切る | **不成立**。反応 0.01〜0.02 回/試合（条件がほぼ起きない）。aware−heal は 5/7 の敵で負け |
| **C2 大技読み（半分以上を盾で受ける）** | 同上、条件を緩和 | **不成立**。反応 0〜0.1 回/試合。aware−heal は 5/7 で負け |
| **C+盾重視デッキ（v0.2 レシピ）** | 攻撃札 4 枚を盾札に置換（大耀） | **不成立**。反応差 0.05〜0.46。単発 4 体で aware は reader にも heal にも負け（−0.8〜−4.7） |
| **D 癒しの構え（大きい予告のラウンドに回復札 → 回復量と同じブロック）** | 未使用の `afterPlay` hook・回復報酬（空き軸） | **部分的**。行動分岐 48〜97%・reader には全敵で勝ち（+3.1〜+17.4）。ただし **heal（常に回復）に 5/7 で負け**（笑蓮）。得意技を持たない寿楽では 7/7 で負け |

※ 参考：既存の 2 つ（v0.2 連撃・v0.3 溜め返し）は Human QA PASS 済みで、同じ指標で reader・heal の両方に勝っている。

## 6. Gate 設計（7 OTOMO 展開用・実装前に定義。すべて baseline 相対）

決定213 の G5（絶対値 100%）の失敗を踏まえ、**絶対値の閾値は置かない**。すべて「同一 seed・同じ条件での相対比較」で判定する。

| # | Gate | 基準 |
| --- | --- | --- |
| EG1 | 行動分岐 | 構えありの対応方策が、同じ盤面で reader と違う手を選ぶ試合が **80% 以上**、かつ **1.0 ラウンド/試合以上** |
| EG2 | 報酬の有無 | 構えありで、対応方策が **reader と heal の両方**に score で勝ち、かつ残HP か撃破R でも heal に勝つ。同一 seed の勝ち越し（高い−低い）が各 seed 群で **+10pt 以上** |
| EG3 | 無条件強化でない | 構えなしでは、同じ対応方策が **最良の代替方策以下**（各 seed 群で Δ ≤ 0） |
| EG4 | 反応が判断で決まる | 反応回数の方策差（対応 − reader、対応 − heal）が **+0.5 以上** |
| EG5 | 勝率を悪化させない | 同一 seed・同一方策で、**構えありの勝ち数 ≥ 構えなしの勝ち数**（決定213 で訂正した形） |
| EG6 | 倍率だけで成立させない | 読まない方策の構えによる score の伸びが **+5 以内**。かつ効果量を 1 段階下げても EG2 が成立する |
| EG7 | 選んで損をしない | 構えありの最良 ≥ 構えなしの最良 |
| EG8 | 見える | 反応が callout・累計・Battle Log の 3 か所で確認でき、要約行がラウンド処理の最後に出る（最新 6 件に入る） |

### Human QA Gate（4 問すべて YES が必要）

1. 敵の予告を見て、自分の行動を変えたか
2. OTOMO を活かすために、カードの使い方・タイミングを変えたか
3. OTOMO が自分の判断に反応したと感じたか
4. 「おすすめどおり」ではなく「OTOMO を使って自分で攻略した」と感じたか
