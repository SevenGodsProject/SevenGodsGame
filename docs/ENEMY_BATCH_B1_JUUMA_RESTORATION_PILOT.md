## 2. Step 2：White Fringe Reconstruction

単純な色置換ではなく、**合成式を解き直す**方法を使った。

```
観測色 C = α·F + (1−α)·B   （B = 白 255）
  → F = (C − (1−α)·B) / α
```

- α=1 の画素では (1−α)=0 なので **計算上まったく変化しない**。牙・毛皮・髑髏の白は構造的に保護される
- α が極端に小さい画素は除算でノイズが暴れるため、近傍の不透明画素の色へ寄せる（**その場所にある色を使うだけで、新しい色は作らない**）

さらに、これだけでは足りないことが分かったため **既知背景マッティング（α の推定し直し）** も実装した：
内側の不透明画素から F を推定し、B が白と分かっているので α を最小二乗で解き、画素を (F, α) に置き換える。

| 段階 | 白フチ（縁が隣接画素より 40 レベル以上明るい割合） |
| --- | --- |
| 現行 Production | **62.6%** |
| 白マット除去のみ（M1/M4・1024） | **20.6〜22.6%** |
| ＋ 既知背景マッティング（M5/M6・1024） | **8.2〜9.9%** |
| ＋ 2 回適用（M8・1024） | **4.8%**（目標達成） |
| 世代 B（目標水準） | 0.2〜5.2% |

**ただし 4.8% を達成した M8 は同一性が壊れる**（§5）。

残った白フチが「元の絵の白（爪・毛皮）」なのかも切り分けた：M6 の 8.2% のうち **元の絵の白は 0.1% だけ**で、**8.1% は汚染**。つまり「juuma は白い部分が多いから仕方ない」という言い訳は成立しない。

## 6. なぜ届かなかったのか（原因の特定）

### 解像度は原因ではない — 対照実験

世代 B の絵を **juuma と同じ本体 359px まで落として**、同じ手順で 1024 へ戻した。

| 対象 | 元 | 359px に落とした状態 | 同じ手順で 1024 へ戻した結果 |
| --- | --- | --- | --- |
| doukeshi | ジャギー 4.4 / 白フチ 0.2% | 4.2 / 0.6% | **1.5 / 0.0%** |
| datenshi | 8.5 / 5.2% | 5.8 / 7.7% | **3.1 / 0.9%** |

**359px の情報量でも、汚染が無ければ白フチ 0%・ジャギー 1.5 まで戻る。** juuma が 20.6% / 11.7 で止まるのは解像度のせいではない。

### 本当の原因

1. 元の切り抜きが付けた **α が実際の被覆率と一致していない**（半透明画素の平均輝度 240.8 に対し平均 α は 122）。合成式を解いても残差が残る
2. 汚染を強く取ろうとすると、**白い毛皮・爪・髑髏が「白マット」と区別できず巻き込まれる**。M8 で白フチ 4.8% を達成した代償が、毛皮の崩壊とシルエットの痩せ（IoU 0.949）
3. つまり「どこまでが背景の白で、どこからがキャラクターの白か」を判断するには、**画素の外側の知識（これは毛皮である・これは刃である）が要る**。純粋な信号処理では原理的に決められない

## 7. 判定と次の一手

**B. RESTORATION INSUFFICIENT。**

元画像だけの非生成修復では、同一性（≥98）と画質（白フチ ≤5%・ジャギー ≤10）を同時に満たせない。次は **元画像そのものを編集する image-to-image restoration**（ChatGPT 側）へ移行する。新規描き直しには戻さない。

### image-to-image へ渡すもの（`art-source/enemies/juuma-restoration-pilot/` に保存）

| ファイル | 用途 |
| --- | --- |
| `juuma-unmatted-native.png`（384×512・透過） | **入力に推奨**。白マットを除いた状態の native 原画。汚染された `art.png` をそのまま渡すより出発点が良い |

### image-to-image に課すべき条件（本 Pilot から導いたもの）

1. **入力画像の内容を変えない**。決定176 の Character Identity Lock 10 項目をそのまま適用する
2. **直すのは縁と解像感だけ**：白い縁の除去、輪郭の階段の解消、毛皮・爪・刃の描き起こし
3. **白い毛皮・爪・髑髏を痩せさせない**。本 Pilot で唯一崩れたのがここ
4. 出力は **透過 PNG・本体高さ 1300px 以上**（決定176 §4-1 と同じ）
5. 受け入れ条件は決定176 §4-3 をそのまま使い、**Identity Match ≥98** を追加する

### 中間案（CEO が望む場合のみ）

M4（白マット除去＋2 段拡大・1024）は Identity 98.3 を保ったまま白フチを 62.6%→20.6%、ジャギーを 22.2→11.7 に下げる。ゲートには届かないが**現行より確実に良い**。image-to-image が難航した場合の保険として提示する（容量 93KB→188KB）。
