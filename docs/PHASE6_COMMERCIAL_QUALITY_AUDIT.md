## 1. 目的と範囲

Phase 5 で戦略性は RC に達した。本監査は「人気商用ゲームと比較したとき、SEVEN GODS のどこが見劣りするか」をゼロベースで洗い出す。機能数の比較ではなく、**最初の 10 秒 → 神を選ぶ → デッキ → 戦闘開始 → カードを出す → 攻撃 → 大技を受ける → 神託 → 共鳴 → 神の一撃 → 追い詰める → 撃破 → 勝利 → 報酬 → もう一度**の体験を対象にした。

変更禁止（遵守）：カード数値／敵数値／stakes／Guard 仕様／神 Passive／Daily seed／Daily 3 attempts／saveVersion／Ranking／Neon／Production env／master／Production。

RC には既に相当量の Game Feel 実装がある（決定128 ほか）。監査はこれを前提に「何が足りないか」を見た。

## 3. 演出タイムラインの実測（MutationObserver、ms＝クリック起点）

| ケース（戦） | cast-flash | HP バー変化 | 着弾表示（シェイク／斬撃／数字／突進） | 備考 |
|---|---|---|---|---|
| 大漁 80（1・恵比寿） | 18 | 977※ | 1052 | ※スクリーンショット同時実行で遅延。順序は同じ |
| 豪快な一撃 140+40（2・大耀） | 51 | **295** | **321**（-140 と -40 が同一フレーム） | 本体と条件⚡追加が分離されない |
| 大喝 180・L3（5・寿楽） | 19 | **460** | **585** | HP が先に減り、125ms 後に着弾 |
| 神託 250・L4（1） | 7 | **744** | **945** | 200ms の「HP だけ減った」空白 |
| 冒険者の勘 → BURST 220（6・福永） | 17 | **322**（敵 HP・自 HP 同時） | 369（数字・シェイク・突進） → **392 で共鳴カットイン開始** | **結果がカットインより先** |
| 一心不乱 → BURST 420 で撃破（2） | 14 | 298（HP 0%・報酬モーダル mount） | 324（撃破！・数字 -420・L4 シェイク）→ 341 カットイン → 1871 神の一撃バナー | **撃破→報酬が神の一撃より先に出る**（§6-2） |
| 敵ターン 通常攻撃（1） | 敵ターンバナー 21 | **774** | 821（突進・シェイク） | HP が突進より 47ms 先 |
| 敵ターン 主砲・神滅甲 360（3） | 98 | **718** | 738（数字、CSS delay で後ろへ）／**750 カットイン開始** | HP バーはカットインの前に減る |
| 敵ターン 双牙乱撃（4） | 18 | — | 740（軽減×3）／773 カットイン | 完全ブロック時 |

**結論**：すべてのケースで「入力 → 即時反応（cast-flash）」は良好（≤50ms）だが、そこから先は **「HP バー → 着弾表示」の順序が逆**で、かつ突進（anticipation）と着弾（impact）が同一フレームに置かれている。商用ゲームの 3 段（anticipation／impact／recovery）のうち**成立しているのは cast-flash の 1 段だけ**。

## 4. CEO 実プレイ指摘 4 点の独立検証

### 4-1. ① 神選択画面：「10 秒以内に 7 神の違いが分かるか」＝ **未達**

実測（1508×660）：画面高 1,303px（4 柱＋3 柱の 2 段）。390px では **3,480px**（7 柱縦積み）。

| 観察 | 評価 |
|---|---|
| 上部に 3 段落の説明文＋凡例ボックス（約 220px）が先に来る | 最初の 10 秒は「読む」に使われる |
| カードの要素順：KV → 型バッジ → 名前 → 台詞 → 戦法 1 行 → 得意技（3 神のみ）→ 神技ヒント（4 神のみ）→ 自己ベスト → **4 軸バー**（最下段） | 比較の主役であるバーが最後（ファーストビューに入らない）。神ごとに要素数が違うためカード高が不揃いで、目が横に走らない |
| 4 軸の数値（攻撃 25／36／21…）は共鳴＋OTOMO 童子の合計値で単位が無い | 「25 と 36 の差」が体感に結び付かない |

### 4-2. ② カードイラスト：60 枚すべて確認

`scripts/phase6-audit/cardSheet.html` で 60 枚（512×768 WebP）を並べ、予言・一心不乱は 1024×1536 の原本も確認した。

**最大の発見：「共通カード 32 枚」と「神専用カード 28 枚」は別の画風で生成されている。**

| 系統 | 枚数 | 画風 | 頭身 | 線 | 塗り | 描画密度 | 背景 | 色温度 |
|---|---|---|---|---|---|---|---|---|
| 共通（attack/guard/resonance/support/hinder/oracle） | 32 | ゲームアイコン的セルルック（`CARD_ART_STYLE_GUIDE.md` の「型」） | 2.0〜2.3 | 中太・均一 | 2〜3 階調 | 低〜中 | 単色地＋エフェクト | タイプ色（赤／青／金／緑／紫／桃） |
| 神専用（7 神×4） | 28 | 神キービジュアルと同系の**厚塗り・高密度・金彩**（`gods/*/keyvisual.webp` に寄せてある） | 2.2〜2.5 | 太め・強弱大 | 多階調・グラデ | **高** | 情景・装飾・文字（大漁／福／玉砕上等!!） | 暖色（金〜橙）に寄る。タイプ色より神の色が優先 |

→ これは**生成時期／プロンプト系統による不統一**であり、「カードタイプによる意図的なアート差」ではない（同じ attack タイプでも共通＝赤セル、専用＝金厚塗り）。ただし神専用 28 枚は**それ同士では一貫している**（各神 4 枚の統一度は高く、キービジュアルとも揃う）。したがって「全部描き直し」は不要で、**枠（フレーム）で 2 系統を包む**か、**専用カードを「神の札」として意図的に別格扱いする**のが現実的（§8）。

**要注意カード**：

| カード | 判定 | 根拠（原本目視） |
|---|---|---|
| **予言**（`card_common_oracle_02`） | **High（要修正）** | ①画面全体がマゼンタ単色に寄り**明度コントラストが低い**（髪・衣装・巻物・床が同じピンク）②**左右に黒い縦帯（各約 8px）が残っている**（スタイルガイド §14 違反）③室内の床・壁が描かれ oracle_01／03 の「渦＋光の帯」と背景の型が違う ④線が細く塗りが柔らかく、隣の 2 枚より 1 段「淡い」。CEO の違和感は ①② が主因 |
| **一心不乱**（`card_taiyo_attack_02`） | **Medium（軽度）** | 画風は大耀 4 枚の中では一貫（厚塗り・金）。共通 attack 9 枚（赤・セル）と並ぶと**黒〜褐色の獣が前景に入り、色温度と密度が最も離れる**。単独の問題ではなく「専用 vs 共通」の系統差が最も強く出る 1 枚 |
| 守護（guard_01）・鉄壁の構え（guard_02） | Medium | 夜の神社・月・城など「情景」背景。共通の型（単色地）から外れる（スタイルガイド既記載） |
| 癒し（support_01） | Medium | 森と動物の情景。密度が support 群で最も高い |
| 闘志（support_06）・見通し（support_07） | Low | 画風は型どおりだが、support 群の少女ではなく attack 群の少年が主役（キャスティングの不統一） |
| 見切り（hinder_02） | Low | 暗く小さく、hinder 群で最も視認性が低い |
| 恵比寿 4 枚 | Medium（既知・C 評価） | 情景・文字・太線。ただし今回の系統分析では「神専用 28 枚の型」の中に収まる |

### 4-3. ③ 戦闘画面の商用品質

敵選択画面（敵立ち絵を舞台背景に合成した 8 枚のカード）は**商用ゲームらしい一画面として成立している**。同じ素材を使う戦闘画面が「置いた印象」になる理由は素材ではなく構図・統合にある。

| 観点 | 実測・観察 | 判定 |
|---|---|---|
| 視線誘導 | 敵（左下 284×304）・神（右上 223×243、宙に浮く）・OTOMO（右下 128）・HP バー 2 本・共鳴ゲージ・神技プレビュー箱・吹き出し・型説明が**一様な重みで散在**。中央（背景の門・階段）が最も明るく、主役がいない | ✗ |
| HUD | 上部バー（ラウンド・神力・スコア）と、スクロール時に貼り付く簡易 HUD（敵 HP・予告・自 HP・神力・共鳴）の**二重構造** | △ |
| HP 表示 | 18px バー・11px 文字。敵 HP バーは敵の下、神 HP バーは神の下（左右で高さが違う）。浮遊数字が **HP バーのラベルに重なって双方が読めない**（例：「-80」が「830/1,030」に重なる） | ✗ |
| Intent | 予告は **13px テキスト**（「🔥 特大 190」）。危険度で色・枠は変わるが、敵側の見た目（構え・オーラ）は溜め以外変わらない | ✗ |
| キャラクター接地感 | 影は drop-shadow のみ。背景には円形の床（アリーナ）が描かれているのに、敵は階段の上、神は空中に置かれ**床に立っていない** | ✗ |
| 背景との光源整合 | 背景は各ステージで暖色（炎・提灯）／寒色（月）だが、キャラは SGG 公式の均一ライティング。神は白マット除去済みだが縁が明るい | △ |
| キャラクターサイズ | 敵 284 ＞ 神 223 ＞ OTOMO 128（意図された序列）。ただし神 KV 640px 由来で「座り／浮遊ポーズ」の神は縮んで見える | △ |
| 情報階層 | 「特大 190」（最重要）と「【重撃型】攻撃が重い」（説明）が同じ 12〜13px | ✗ |
| 余白 | アリーナ 702px の中に 10 種類の情報。手札は別領域 | △ |
| フォント | `system-ui, Segoe UI, Hiragino, Noto Sans JP`。**見出し用書体が無い**（撃破！・神の一撃！も同じ書体の太字） | △ |
| 状態異常 | バッジ「攻撃力 -50（1）」は 11px・低コントラスト。敵の見た目は変わらない | △ |
| ダメージ表示 | 15〜34px、白抜き赤字。HP バー上に出るため背景と敵の間で埋もれる | ✗ |
| スマホ 390px | レイアウトは破綻しない（2 列手札・sticky HUD・auto focus）。ページ高 **2,367px**（敵 279 → 手札 1,471 → 託宣 1,890 → 終了 2,159） | △ |
| 背景の情報密度 | 3D レンダ調の高密度背景（門・提灯・炎・階段）が UI より強い。減光は 0.13〜0.27（`#05060d22〜44`）と弱い | ✗ |
| 神／敵／OTOMO の描画密度差 | 敵＝暗色・高密度の厚塗り、神＝公式キットの線画セル、OTOMO＝単色マスコット。**3 種類の画風が同居** | ✗ |
| **768p ラップトップ問題（新規）** | CSS viewport 高 660 に対しアリーナが 702px。**開始時に敵 HP バー（y=675）と予告（y=698）が画面外**。手札は y=940。さらに PC 幅では「ラウンドを終える」が `position:fixed` で**手札の上に重なる**（実測・スクリーンショットで確認） | ✗✗ |

「既存素材のまま商用ゲームらしい一画面に統合できるか」→ **できる**。必要なのは素材ではなく、①敵と神を同じ床面に立たせる（接地影・床の楕円）②背景の減光を UI 周辺で強める（周辺減光）③HP・予告を「キャラの真上／真下」に固定した 1 枚の名札にまとめる ④予告を 20px 以上にし敵のポーズ／オーラを連動 ⑤768p でアリーナ＋手札 5 枚が同時に入る高さ（アリーナ ≤ 420px 程度）。

### 4-4. ④ 戦闘の爽快感：「HP ゲージを減らす作業」＝ **実測で裏付け**

「攻撃した／効いた／大ダメージを与えた／追い詰めた／倒した」の 5 段階の区別：

| 段階 | 視覚 | 音 | 時間 | 区別できるか |
|---|---|---|---|---|
| 攻撃した | cast-flash（タイプ PNG）・神の突進 0.45s | card_play（0.3） | 280ms 後に結果 | ○（唯一きちんと存在） |
| 効いた | シェイク 2〜7px・斬撃線・数字 15〜19px・HP バー 0.2s | hit_l1/l2 | 着弾が突進と同時 | △（80 と 140 の差は数字の大きさだけ） |
| 大ダメージ | L3/L4：11px シェイク・大斬撃・34px 数字・音量 1.0 | hit_l3/l4 | hit stop 無し | △（100 と 300 の差＝**数字 19px→34px と振幅の差**。体感差は小さい。「ラウンドを終える」ボタンや背景の門は微動だにしない） |
| 追い詰めた | **なし**（敵 HP 50%／25%／瀕死で敵・背景・BGM・HP バー色が変わらない） | なし | なし | ✗ |
| 倒した | 「撃破！」1.0s → 報酬モーダル。**敵は倒れず立ったまま暗転**。最後の一撃はそのカードの tier（第 1 戦は一撃 50 で **L1＝最小演出**で撃破） | victory_sting | 1.0s | ✗ |

クリティカル相当の瞬間（条件⚡成立）：追加効果は本体と同一フレームで「-140」「-40」が同じ位置に重なる。⚡は手札で光るが、着弾では区別されない。

敵の被弾反応：シェイク＋明度フラッシュのみ。怯み（ポーズ変化）・ノックバック・色変化・粒子・画面揺れ・hit stop はいずれも無い。

**結論**：CEO 仮説は正しい。原因は素材でもバランスでもなく、**(a) 着弾前に HP が減る順序 (b) 5 段階のうち「追い詰めた」「倒した」が未実装 (c) 大ダメージの差分が数字サイズに依存**の 3 点。すべて表示層（`src/components/battle`）で解決できる。

## 6. 神の一撃 監査

### 6-1. 現状の流れ（実測）

共鳴 7 到達 → **同一フレームで敵 HP 減少・トースト「⚔ 敵に220ダメージ」・数字**（T+322〜369）→ 共鳴カットイン（T+392、0.9s、キービジュアル＋「福永、共鳴発動！」）→ バナー「✨ 神の一撃！」（T+1.87s）＋神の突進 → 着弾（数字は CSS delay で T+1.26s 相当に再表示）→ OTOMO 成長バナー。

問題：
1. **結果が先に見える**（静止撮影で確認：カットインの暗転の下に「敵に220ダメージ」と減った HP バーが透けている）。「発動 → 溜め → 技 → 着弾 → 大幅減少」の順が逆
2. **致死時は連鎖が崩れる**：撃破 → 「撃破！」 → 報酬モーダルが T+1.3s に出て、神の一撃バナー（T+1.87s）と着弾がモーダルの裏で再生される。**一番気持ちいいはずの「神の一撃でとどめ」が見えない**（第 2 戦）
3. カットイン 0.9s の間、画面は暗転＋静止画。「溜め」の緊張（画面揺れ・音の上昇）が無い
4. hit stop なし。着弾は L4 シェイク（11px）と 34px 数字。通常の L3 との差が小さい
5. 「共鳴 7」到達のゲージ発光は 0.9s あるが、カットインが直後に被るので視認できない

### 6-2. 理想の流れと推奨時間（合計 ≒ 2.4s、現行 2.3s と同等でテンポは壊さない）

| 段階 | 内容 | 時間 |
|---|---|---|
| 到達 | ゲージ満タン発光＋上昇音（既存） | 0〜300ms（カットイン開始を 300ms 遅らせる） |
| 発動 | 暗転＋キービジュアル slide-in（既存）。**この間 HP バー・トースト・数字を出さない** | 300〜1,000ms |
| 溜め | 神が構える（既存 `god-lunge` の前半を 150ms 伸ばす）＋低音の上昇 | 1,000〜1,300ms |
| 技 | 突進＋斬撃（既存） | 1,300〜1,450ms |
| **hit stop** | 全アニメ停止 **90ms**＋画面フラッシュ 1 フレーム | 1,450〜1,540ms |
| 大ダメージ | 数字 34px→48px・画面揺れ（`.battle` 全体 4px）・**HP バーが 0.5s かけて減る**（ゴーストバー） | 1,540〜2,100ms |
| 敵大リアクション | 被弾ポーズ（`scaleX(0.96)`＋後退 12px）＋明滅 | 同上 |
| 後始末 | OTOMO 成長バナー（既存） | 2,100〜2,400ms |
| **致死時** | 上記を完走してから「撃破！」→ 敵崩壊 → 報酬（報酬は撃破の 1.5s 後） | +1.5s |

engine は不変（結果は同一トランザクションで確定済み）。変更は「見せる順番」だけで、`enemyVfxTiming.ts` に定数を足し、`useFloatingNumbers`／`EnemyPanel`／`BattleScreen` の遅延に反映する既存パターンで実装できる。

## 7. 撃破／勝利 監査

現状：最後の一撃 → 同フレームで HP 0 → `victory-beat`「撃破！」1.0s（文字のみ。敵は立ったまま暗転）→ 報酬 3 択 → 結果カード（勝利／神域制覇／「自己ベストまであと N 点」→ ポートレート → スコア 0 からロールアップ → 内訳 → 神技評価 → ボタン）。

| 観察 | 問題 |
|---|---|
| 第 1 戦のとどめは「一撃 50+30」＝ **L1（最小演出）**で撃破 | 最後の一撃が一番弱い演出になり得る |
| 第 3 戦のとどめは蒼毘の得意技（ラウンド終了時の反撃 30）で敵 HP 20→0 | **着弾演出ゼロで勝利**（ログに「敵に30ダメージ」だけ） |
| 敵は倒れない・消えない | 「倒した」の視覚が無い |
| 勝利カードの 3 行目に「自己ベストまであと 3,760 点」が**スコアより先に**出る（スコアは 0 表示から 0.6s 後にロール） | 祝う前に不足を告げる順序 |
| ポートレート 112px。結果カードは内部スクロール付きの長いリスト | 祝祭感より帳票 |

**最小構成の提案（3 分ゲームのテンポに合わせ、合計 +1.5s 以内）**：

| 要素 | 採用 | 時間 |
|---|---|---|
| 最後の一撃は**カードの tier に関わらず L4 扱い**（`enemyHitTier` を `status==='won'` の時に上書き。表示専用） | ○ | 0 |

| 敵 flash（白→通常）＋画面揺れ 4px | ○ | 200ms |
| 専用 SE（既存 `hit_l4`＋`victory_sting` を 120ms ずらす） | ○ | — |

| HP バー finish（0 まで 0.4s で減り、バーが白く発光して消える） | ○ | 400ms |
| 「撃破」文字（既存 `victory-beat` を敵崩壊の**後**に出す） | ○ | 800ms |
| 勝利 BGM transition（既存ジングル、着弾直後ではなく「撃破」表示時に開始） | ○ | — |
| 報酬は「撃破」表示終了後 | ○ | — |
| 得意技・DoT 等の**非カード撃破**も同じ演出を通す（`GAME_ENDED` を起点に統一） | ○ | — |
| FINISH／討伐の派手なカットイン、カメラ寄り、スローモーション | ✗（過剰） | — |

## 14. RC を先に公開するか（AI 判断）

比較：

| 案 | 利点 | 欠点 |
|---|---|---|
| A：RC のまま先に公開 | 公開が早い。Phase 5 の戦略性は完成 | 初見プレイヤーが最初の 1 戦で受けるのは「作業感」（本監査で 7/7 戦「攻撃の手応え△」）。Production の Phase 3 版から一気に上げる価値が伝わりにくい |
| **B：小規模 Game Feel Patch（6-A）を入れてから公開** | 最も体感差の大きい層（G/M/K/N）を表示専用で埋められる。回帰リスクは低い（engine・save 不変、`feelTier`／`enemyVfxTiming` の既存パターン） | 公開が 1 週間前後遅れる |

**採用：B**。理由は「爽快感」が CEO の最重要体感であり、かつ修正が表示層に閉じて低リスクであること。ただし **上限 1 週間（表示専用・テスト PASS・gameVersion 不変）**を条件とし、超えるなら 6-A の完成部分だけで RC を切り直すか、RC のまま公開する。6-B 以降は公開後でよい。

## 15. Known Risks

- 神の一撃の順序変更は、カード自身の効果＋BURST が同一バッチのときの数字の並びを変える。既存の `VFX-03` のハンドオフ（`onAnimationEnd` 起点）を崩さず、遅延定数の追加だけで済ませること
- hit stop の実装は `document.getAnimations().pause()` ではなく、対象要素の `animation-play-state` で行う（本監査でページ全体を pause したところ、カットインの `animationend` が取りこぼされて操作不能になった。**これは監査ハーネス側の副作用であり製品の不具合ではない**が、同じ落とし穴がある）
- 768p 対応でアリーナを縮めると 1080p では余白が増える。`min-height` ではなく `clamp()` で両立させる
- 背景タブ（`visibilityState: hidden`）では CSS アニメーションと `setTimeout` が抑制され、本監査中に演出のハンドオフが止まる場面があった。実機の通常操作では起きないが、E2E は前面タブで実行すること
- SFX の収録素材採用はライセンス判断（CEO）。自作層化までは AI 側で可能
- 予言の再生成は画像生成（CEO 作業）が必要。スタイルガイド §12・§14 の条件をプロンプトに明記する
