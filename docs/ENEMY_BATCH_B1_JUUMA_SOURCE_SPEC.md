### 1-3. pose / 構え

- **四つ這いに近い前傾の獣人**。後脚で体を支え、上体を起こして正面（やや viewer 右）を向く
- 頭部は正面やや右向き、口を大きく開けて咆哮
- **右腕（viewer 右）を頭上へ振り上げ**、**左腕（viewer 左）を下げて**爪を地面方向へ広げる **左右非対称の構え**
- pose angle：上体はやや前傾、両腕が作る対角線は左下→右上（以下 2 行はいずれも**目視の概算**であり実測値ではない）
- head/body ratio：顔（たてがみを除く額〜顎）は本体高さの約 **0.16**、たてがみ込みの頭部塊は約 **0.30**。頭身は「四つ這いで体を畳んでいる」ため立ち姿の頭身では表せない。**顔の大きさと本体高さの比 0.16 を維持すること**を要件とする

## 3. 改善対象（弱点の分類と数値）

世代 B の 3 体を基準に測定した。**A〜D は実データで確認、E・F は測定上は不足していない。**

| 分類 | 指標 | juuma | 世代 A 平均 | 世代 B | 判定 |
| --- | --- | --- | --- | --- | --- |
| **A 低解像度** | native 本体高さ | **359px** | 359〜464px | 1302〜1446px | **該当（最重度）** |
| | Production への拡大率 | **1.203×** | oni 0.94／onryo 1.00／ryujin 1.00 | —（縮小のみ） | **juuma だけが拡大** |
| **B ドット調 / jagged** | 輪郭の方向反転／100 行 | **22.2** | 25.2〜26.2 | **4.4〜8.5** | **該当**（世代 B の 3〜5 倍） |
| **C 白フチ** | 縁が隣接画素より明るい割合 | **62.6%**（平均 +64.7） | 57.5〜87.4% | **0.2〜5.2%**（平均 −11〜−60） | **該当（最優先）** |
| **D 細部潰れ** | 359px を 432px へ拡大 | 情報は増えず、輪郭が鈍る | — | — | **該当**（A の帰結） |
| **E 陰影不足** | コントラスト | 59.9 | 48.1〜62.6 | 55.3／60.9／60.7 | **非該当**（同帯） |
| | 影／中間／ハイライト | 50.7／41.8／7.4% | — | 48.4〜63.7／28.7〜43.5／6.9〜8.1% | **非該当** |
| **F 質感不足** | 局所 SD p90 | 44.2 | 45.9〜54.0 | 38.6／49.9／49.0 | **非該当**（同帯） |

**読み方**：juuma が「のっぺりして見える」「線が汚い」のは、**陰影や質感の設計が悪いのではなく、①原画が 359px しかない ②白背景から切り抜いたため縁に白マットが残っている ③それを 1.2 倍に拡大している**——この 3 つの複合である。したがって再生成では「陰影を強くする」ではなく「同じ絵を十分な解像度で、透過で、正しく描き直す」ことが要件になる。

## 4. 再制作の仕様

### 4-1. 生成物（CEO の生成工程へ渡す要件）

| 項目 | 要件 | 理由 |
| --- | --- | --- |
| 形式 | **透過 PNG**（アルファ付き） | 切り抜き不要にして白フチの再発を断つ |
| 本体サイズ | **高さ 1300px 以上**（世代 B と同等。最低でも 900px） | 768px asset の本体は 653px。縮小で情報が余る状態にする |
| 背景 | **完全透明**。白背景・単色背景での生成＋後切り抜きは**禁止** | 白フチ 62.6% の直接原因 |
| 構図 | 単体・全身・切れなし。余白は上下左右に均等に少し | 後段で bbox 基準に再配置するため |
| 画風 | **世代 B（datenshi／karakuri／doukeshi）と同じ painterly** | 敵 7 体の世代差を解消する（決定173） |
| 同一性 | §2 の 10 項目をすべて満たす | 別キャラクター化の防止 |
| 枚数 | 候補を複数（3〜5 案）。1 枚で決め打ちしない | 同一性チェックで落ちる可能性があるため |

### 4-2. 最終 asset への書き出し（Batch A と同じパイプライン）

```
生成された透過 PNG（本体高さ ≥1300px）
  → 本体の最大連結成分 bbox を抽出
  → 768×768 の透過キャンバスへ、現行 juuma と同じ構図比で配置
       body height ratio 0.8438（= 本体高さ 648px）
       center X 0.5059 / bottom 0.9238
       body aspect 0.9907（横に広いシルエットを維持）
  → WebP quality 90 / alphaQuality 100 / effort 6
  → 可逆参照比 PSNR ≥33dB を満たさなければ最小限まで quality を上げる
  → ファイル名は `art_hq.webp` のまま（src・CSS・enemies.ts 無変更）
```

構図比は**現行 juuma の実測値をそのまま使う**（世代 B 標準の 0.8496 ではない）。理由：画面上の見かけの大きさと位置を変えないため。世代 B 標準に合わせると本体高さが +0.7% 変わる。差は許容範囲だが、Batch B-1 では「画質だけを直す」ことに絞る。

想定容量：本体が横に広いぶん datenshi（181KB）と doukeshi（178KB）の中間、**170〜200KB**（現行 93KB から +80〜110KB）。

### 4-3. Acceptance Criteria（受け入れ条件）

| # | 条件 | 閾値 | 測り方 |
| --- | --- | --- | --- |
| 1 | 同一性 | 現行 asset との**勾配相関 ≥0.80**（別キャラなら 0.3 前後に落ちる） | `enemy-visual-batch-a/verify-sources.mjs` と同じ指標。ただし絵を描き直すので Batch A の 0.95 基準は使えない |
| 2 | 同一性（目視） | §2 の 10 項目すべてを満たす | CEO と AI の双方で 1 項目ずつ確認 |
| 3 | **白フチ** | 縁が明るい割合 **≤5%**（世代 B 並み） | `weakness.mjs` の fringe |
| 4 | **ジャギー** | 輪郭の方向反転 **≤10／100 行**（世代 B は 4.4〜8.5） | `weakness.mjs` の jaggedness |
| 5 | 解像度 | source 本体高さ ≥1300px、拡大率 **1.0 未満**（必ず縮小になること） | 書き出しログ |
| 6 | 構図 | 位置差 ≤2 CSS px・サイズ差 ≤2% | `enemy-visual-batch-a/export.mjs` の構図ロック |
| 7 | 符号化 | 可逆参照比 PSNR ≥33dB | 同上 |
| 8 | 色味 | 主要 7 色（§1-4）の配置が一致。彩度・色温度の大きな変更なし | `analyze.mjs` の dominantColors / style |
| 9 | 表示 | 4 viewport × DPR1/2 で scroll 0・overflow 0・敵要素ボックス差 0px | `enemy-visual-audit/capture.mjs` |
| 10 | 回帰 | tests / typecheck / lint / build、gameVersion `1.80c6eda23ed082dc`・saveVersion 9 不変 | 既存ゲート |

### 4-4. スコア目標

現行 45/100。Batch A の 3 体が 87〜91 に達したことを踏まえ、**80 以上**を目標とする。内訳の想定：輪郭 6→18、内部ディテール 7→14、圧縮 11→14、DPR2 耐性 4→15、背景 7→8、神との差 3→9、Mobile 5→6、第一印象 2→4 ＝ **88**。

## 決定176（提案）

**Enemy Batch B-1「双牙の魔獣 / juuma」Source Art Reconstruction Spec を確定。** native 原画が 384×359px しか存在せず Production が 1.203 倍に拡大していること、白フチ 62.6%・ジャギー 22.2/100 行が世代 B（0.2〜5.2%・4.4〜8.5）と隔絶していることを実測で確認し、**再生成が必要**と判定した。陰影・質感は測定上は不足していないため、要件は「同じ絵を十分な解像度で・透過で・正しく描き直す」に絞る。Character Identity Lock 10 項目・生成要件・書き出し仕様・受け入れ条件 10 項目を本書に確定。**画像生成・asset 変更・master 変更は行っていない。**
