## 1. 監査：どこに置くか

| 画面 | 現状 | 判断 |
|---|---|---|
| `HomeScreen` | 神選択・神域挑戦・戦績への入口 | **置かない**。ホームは導線であって情報を読む場所ではない |
| `DailyChallengeScreen` | ボス紹介 → `daily-facts`（SEED / 今日の自己ベスト / 残り挑戦回数）→ 神別ベスト → ルール → 開始 | **ここに置く** |
| `GameOverOverlay` | `daily` が渡ったときだけ「今日のベスト更新」「残り回数」を出す節が既にある | **導線だけ足す** |
| `RecordScreen` | 7日ぶんの履歴 | 置かない（過去の話であって「今日」ではない） |

### 置き場所と、その理由

**`daily-facts` の直後、神別ベストの前。**

あの3枚は既に「今日の自分」を示している（自己ベスト・残り回数）。順位はその自然な続きで、
**自分 → 全体の中の自分 → 神別の履歴 → ルール → 開始** と、粒度が広がってから行動に戻る流れになる。

ボスより上には置かない。ここは**挑戦する画面**であって順位表ではなく、
最初に目に入るべきは今日の敵である。

CEOにA/B/Cを出さず1案に決めた（Phase 4.9 の指示どおり）。

### 2-1. なぜ `rankingClient.ts` に相乗りしなかったか

あちらは**提出**（start / submit）で、「`submissionEnabled` が false の間は一切通信しない」という
約束を持つ。ランキングの表示は**読むだけ**なので、その約束の対象外。

相乗りさせると「提出は閉じているが順位は見せたい」という現在の状態を表現できない。
kill switch はサーバー側の env で Preview だけ開ける設計なので、**クライアント定数では切り替わらない**
——つまり `submissionEnabled` で取得を止めると、Preview でもUIを確認できなくなる。

### 2-2. 表示するもの（Phase 4.9 の必須項目）

| 項目 | 出どころ |
|---|---|
| 自分の順位 | `self.rank` |
| 自分のベストスコア | `self.score` |
| 今日の挑戦人数 | `totalPlayers` |
| Top 10 | `rows`（`limit=10` で取得） |
| 同点順位 | `rank`（サーバーの値をそのまま） |
| 同点人数 | `tiedCount` |
| 上位何% | `topPercent` |
| 残り挑戦回数 | 既存の `daily-facts`（localStorage）に既にある |

### 2-3. 順位は作り直さない

`rank` / `tiedCount` / `topPercent` / `pointsToNextRank` は**サーバーが計算した値をそのまま出す**。
クライアントで並べ替えも順位付けもしない。規則は決定133 の `assignRanks` ただ1つで、
二重実装するといつか食い違う。**「並べ替えていないこと」自体をテストで固定した**
（わざと順位が乱れた配列を渡し、順序が保たれることを確認）。

### 2-4. 匿名IDの見せ方

`playerId` は32桁の16進。生値をそのまま並べても読めず、端末を跨いだ追跡の手掛かりにもなる。
**先頭4桁だけ**を大文字で見せる（`プレイヤー 3574`）。自分の行は名前そのものが **「あなた」** になる。

> 実装中に「あなた ← あなた」と二重に印が付いていたのを実機で見つけて直した。
> 読み上げも重複するので、見分けは**名前の文字**が担い、色と左の帯は補助に落とした。

### 2-5. ランキングが無くてもゲームは壊れない

`fetchDailyLeaderboard` は**例外を投げない**。すべての失敗が案内文1行に落ちる。

| 状態 | 表示 |
|---|---|
| 取得中 | 「ランキングを読み込んでいます…」 |
| 404 / 503（未deploy・env未設定・DB未接続） | 「今日のランキングはまだ準備中です。」 |
| 500・壊れた応答 | 「ランキングを取得できませんでした。時間をおいて開き直してください。」 |
| 通信断・時間切れ（6秒） | 「ランキングに接続できませんでした。通信環境をご確認ください。」 |
| 0人 | 「今日はまだ誰も記録していません。最初の一人になれます。」 |
| 自分の記録なし | 「今日はまだ記録がありません。挑戦すると順位が付きます。」 |

**「まだ始まっていない」と「壊れている」を同じ文言にしない。** 実際に状態が違う。
挑戦開始のボタンには一切触れないので、**オフラインでも神域挑戦はそのまま遊べる**。

### 2-6. 「送信できる」と誤解させない

`submissionEnabled` が false の間は、パネルの末尾に必ず出る：

> 現在は閲覧のみです。今日の挑戦結果はまだランキングに登録されません。

提出が開けば自動的に消える。決着画面にも同じ趣旨の但し書きを出す。

### 2-7. 決着画面（Daily のときだけ）

既存の `game-over-daily` の節の中に、最終スコアと「今日のランキングを見る」を足した。
`daily` が null の通常モードでは**節ごと現れない**。導線は
`GameFlow` → `BattleScreen` → `GameOverOverlay` と `inDaily` / `state.mode === 'daily'` で
二重に絞ってあり、3か所すべてをテストで固定している。

## 3. モバイル縦画面

- 既存の折り返し幅 **640px** に合わせた（daily.css の他の指定と同じ）
- 上位一覧は **max-height + 内部スクロール**。画面を縦に伸ばし切らない
  （実測：デスクトップ幅で一覧304px・パネル全体512px。640px以下ではさらに詰まる）
- Top100 を常時表示しない。**10件だけ**出し、超えるぶんは「上位10人を表示（全N人）」と伝える
- 固定幅を持たない。360px に絞って実測し、**横あふれ 0**・表も横スクロール不要で収まることを確認
- 決着画面のリンクは **min-height 44px**（Apple HIG）

## 4. アクセシビリティ

| 項目 | 対応 |
|---|---|
| 色だけで区別しない | 順位は必ず「N位」の**文字**。自分の行は名前が「あなた」。同点は「N人が同順位」の文字 |
| 読み上げ | `role="status"`（読み込み中・失敗・0人）、`aria-label`（領域・表） |
| タップ領域 | 決着画面のリンク 44px。パネル内に小さな押下要素を作っていない |
| 長い文字列 | **切り詰めない**（このリポジトリの方針）。`overflow-wrap: anywhere` で折り返す |
| 数字 | `font-variant-numeric: tabular-nums` で桁を揃える |

## 6. Known Risks

| # | 内容 | 影響 | 緩和 |
|---|---|---|---|
| 1 | 提出が閉じている今、**自分の順位は永久に出ない**（記録されないため） | 「参加できない順位表」を見せることになる | 但し書きを常時表示。開けば自然に解消する |

## 7. Preview QA への次の1手（UI-8）

**push はまだしていない。** Preview で確認する段になったら：

1. branch を push（Preview が自動で建つ）
2. Preview スコープの `RANKING_API_ENABLED=1` と `RANKING_DATABASE_URL` は**まだ生きている**
   （決定147 で残したまま）。再デプロイされれば読み取りは通る
3. 実機の縦画面で神域挑戦の画面を開き、次を見る
   - 参加者がいる日：Top10・自分の行・同点表示・「全N人」
   - 参加者がいない日：「今日はまだ誰も記録していません」
   - `RANKING_API_ENABLED` を外した状態：「まだ準備中です」
4. `RANKING_PREVIEW_UNLOCK` を入れて実際に1回遊び、**自分の順位が付く**ところまで見る
   （入れたら**必ず再デプロイ**。決定147 の落とし穴）
5. 終わったら `RANKING_PREVIEW_UNLOCK` を外して再デプロイ

**Production には触れない。** 公開判断は §6-3 の CEO 事項のまま。
