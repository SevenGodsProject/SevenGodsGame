**推奨（1案）：神Passive 3神 ＋ 専用カード4枚への条件付き追加効果。新ルールは2種類、変更カードは4枚、共通カード・BURST・OTOMO・神階modifier・おすすめデッキは無変更。**

| 項目 | 推奨内容 |

## 5. Passive Necessity Analysis

| 問い | 結果 |
| --- | --- |
| Passive は必要か | **必要**。条件Effectのみ（B1）は蒼毘は救うが笑蓮・福永を救えず（stress 24〜26%）、fortress／control が最良になる神は0。数値差し替えのみ（D1）は全神一律に上がるだけで最良プロファイルは変わらない |
| 何神に必要か | **3神（蒼毘・笑蓮・福永）**。Step 1 で「看板の戦い方が死んでいる」3神に一致。恵比寿・大耀・才華は攻撃／手数で既に最適行動と看板が一致し、寿楽は control／fortress が既に最良（C0 stress で fortress +8.9pt） |
| Passiveの性質 | 採用3件は全て「防御・回復・窮地 → 火力」の**変換**。純粋強化（大耀・才華案）は判断を変えず不採用。「その神らしい行動を取ると勝てる」を作るのは変換型のみ |
| Passive単体で勝率を壊さないか | 神階0は全神100%（Safety）。神階Ⅳ normal は蒼毘 83.9→100%、他神不変。神階Ⅶ normal で最強神（寿楽・蒼毘）が100%に達するが、現行の寿楽（97.6%）と同水準で天井の位置は変わらない |
| OTOMO進化はIdentityに必要か | 全構成で試合終了時の形態は平均0.7〜1.3（incarnate 1回）で不変。Passive案はOTOMO進化に依存させていない。「OTOMO進化が神Identityの一部になっていない」ことは **Root Cause として記録し、Phase 4（OTOMO再設計）へ送る** |

## 6. Conditional Effect Architecture Analysis

### 6-1. 比較した方式

| 方式 | 概要 | 評価 |
| --- | --- | --- |
| (a) Effect内 conditional | `Effect` 型に `when?` を持たせる | `applyEffect` の全分岐に条件評価が入り、本体効果と追加効果の区別がUI・ログで曖昧になる |
| (b) 既存Effectを参照する predicate | 「直前のeffectがblockなら…」 | 順序依存が強く説明文が長い。60枚規模では過剰 |
| (c) category / tag ＋ 神別倍率 | タグ一致で+X% | 属性一致buffに収束（禁止事項）。判断を変えない |
| (d) event-based trigger | イベント購読 | rule engine化。rngCursor／リプレイの扱いが複雑化 |
| **(e) カード単位 `bonus: { when, effects }`（採用）** | `CardDef` に `bonus?` を1つ。`when` は小さな列挙、`effects` は既存 `Effect[]`。`playCard` で本体の後に1回評価 | 説明文が「本体。条件なら追加」の1行。`Effect` 型無変更。評価関数は1つ。将来もデータ追加のみ |
| **God Passive（採用）** | `GodDef.passive?: { id, textJa, hooks }`。フックは `afterPlay`／`afterEnemyTurn` の2種で足りる（採用3件：蒼毘＝afterEnemyTurn、笑蓮・福永＝afterPlay）。効果は既存 `Effect[]` | 神IDのif分岐をengineに書かず神定義データに閉じる。Mastery集計の「神を見て集計する」既存パターンの延長 |

**採用＝(e)＋God Passive。** 新Effect種別・新resource・新UIリソースを増やさない。Step 2 ハーネス（`scripts/phase3-audit/step2/harness2.ts` の `Passive`／`CondEffect`／`step()`）が本番の外側でこの2構造をそのまま実装しており、engine移植時のリファレンスになる。

### 6-2. 不変ルールとの整合

- 不変ルール3（`if (card.name)` 禁止）：条件はデータ、評価関数は1つ。Passiveも `GodDef` データ。
- 不変ルール2：追加効果は `createRng(seed, rngCursor)` で本体に続けて適用し `rngCursor` を進める（ハーネスで実証。draw を含む条件効果もリプレイ可能）。
- 不変ルール4：+50%・半分・6ダメージ等の値は `rules.ts` に集約する。
- 不変ルール5：GameState 構造は不変。表示用に `BONUS_TRIGGERED`／`PASSIVE_TRIGGERED` イベントを足す程度。saveVersion bump 不要見込み。

### 6-3. 採用に必要な条件語

`blocked`（ブロックが敵の予告以上）／`enemyBig`（敵の予告合計10以上）／`lowHp`（HP半分以下）の3種のみ。Passive は `fullHp`／`lowHp`／「敵ターン後の残ブロック」を内部で使う。**Cond列挙は将来拡張できるが、FINAL SPEC ではこの3〜4種に限定する。**

## 17. Phase 3 FINAL SPEC への残課題

1. **Gate 4（専用負価値 13〜14/28）**：残る負価値札は数値・条件の個別調整が必要。FINAL SPEC で「第2波：4枚」（懐の深さ／誓いの盾／幸運の女神／姉御の号令）の条件付き効果を pilot し、8枚以下を狙うか、Phase 4 カード整理へ送るかを決める。
2. **Gate 5（報酬一致率 46%）**：Passive／少数カードでは構造的に動かない。案：報酬3択の提示を神別に重み付け（神の専用札・Passiveと噛み合う型を優先）。引継書 §21「Phase 3 で Reward 全面改修はしない」に従い、**Phase 4 候補**として記録。
3. **Gate 3 の測定器**：使用率は天井で無効。先頭カード種別・dWin は 1,000デッキ/神で再測定する（FINAL SPEC 前に1回）。
4. **笑って許す**の条件／効果再調整（負価値 −12 のまま）。
5. **福永の「大勝負」の表現**：AIプロファイルに「HPを低く保つ」型が無いため最良に現れにくい。人間プレイでは「回復を我慢して殴る」判断が発生する見込みだが、Human Play QA で確認する項目にする。
6. **OTOMO進化**が Identity に寄与していない（形態平均0.7〜1.3）→ Phase 4（OTOMO再設計）へ記録。
7. **おすすめデッキ**：統一は不採用。Phase 4 で「Passiveに合わせた神別設計」と「3AP火力札枚数の上限」を扱う。
8. **神階Ⅶ天井**：蒼毘・寿楽が normal で100%。神階Ⅷ（または神階Ⅶの選択追加）は別Phase。
9. saveVersion／イベント追加の要否、`rules.ts` のキー設計、Mastery（蒼毘「鉄壁」＝無傷受け率）との整合（反撃はブロック残量を消費しないため影響なし、要テスト）。
