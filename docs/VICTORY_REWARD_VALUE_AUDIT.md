## 1. 事実（コード実物）

### 1-1. 初期デッキ編成で選べるカード pool
- `getCardPoolForGod(godId)` ＝ **共通 32 枚 ＋ その神の専用 4 枚 ＝ 36 枚**（`deckBuilder.ts:24`）。他神の専用は不可。
- デッキは 20 枚ちょうど・同一カードは `maxCopiesPerCard=2` まで（`rules.ts`）。
- おすすめデッキ：v4 固定デッキ（恵比寿・蒼毘・才華・寿楽）は「共通カードは原則 1 枚」。生成式（大耀・福永・笑蓮）は専用 ×`recommendedExclusiveCopies`（2。蒼毘／寿楽／笑蓮は 1）＋共通を種別目標で 1 枚ずつ（`deckBuilder.ts:131–135, 252–300`）。**おすすめデッキに 3 枚積みは存在しない**。
- レアリティ：共通 28 common ＋ 4 rare、専用は全 28 枚 rare。`rarity` は表示（枠色）専用で engine は参照しない。

### 1-2. 勝利後 3 択で出るカード pool
- `RewardOverlay` は `getCardPoolForGod(godId)` を**そのまま**母集団にし、`pickRewardCandidates(pool, seed+'-reward', 3)`（seed 付き Fisher–Yates）で 3 枚を選ぶ（`RewardOverlay.tsx:27–29`）。重み付け・除外・デッキ参照は**なし**。
- 同じ seed なら同じ 3 枚（決定論・決定43）。

### 1-3. 重複率／報酬専用カード
- 報酬 pool ⊆ 編成 pool、かつ同一集合：**重複率 100%**。**報酬専用（reward-only）カードは 0 枚**。
- 3 択に専用カードが 1 枚以上含まれる確率 ≈ 1 − (32/36)(31/35)(30/34) ≈ **30.6%**。3 枚とも共通 ≈ 69.4%。

### 1-4. 報酬を取ったとき実際に変わるもの
- `addRewardBonus(godId, cardId)` → localStorage `sevengods.rewardBonuses[godId][cardId] += 1`（`rewardStorage.ts:62`）。**上限なし**（同じカードを取り続ければ 4 枚・5 枚…まで積める）。
- 効く場所は `getMaxCopies` ＝ `2 + bonus` の**編成上限だけ**（`deckBuilder.ts:33`）。デッキ枚数 20・AP・スコア・敵・OTOMO・神階・託宣には**一切影響しない**。
- 編成画面には「報酬で上限+n」バッジが出る（`DeckBuilderScreen.tsx:286`）。
- **おすすめデッキには自動反映されない**（`getRecommendedDeck` は bonus を見ない）。プレイヤーが編成画面で手動で 3 枚目を足して初めて効果が出る。

### 1-5. deck limit／copy limit への影響
- デッキ上限 20 枚は不変。copy limit のみ +1/回・無上限。
- 3 枚目を積むには「同じカードを 2 枚すでに入れている」ことが前提。おすすめデッキでは専用カード（2 枚積みの神のみ）だけがこの前提を満たす。

### 1-6. 次戦への影響
- 手動編成しない限り **0**。「即開始」「おすすめデッキに戻す」導線では報酬が一度も機能しない。

### 1-7. Daily（神域挑戦）への影響
- Daily では `bonusCopies` を**空 Map で固定**（`DeckBuilderScreen.tsx:101–102`、`GameFlow.tsx:345`）。画面文言も「神域挑戦では報酬カードの追加編成上限（通常モードの 3 枚積み）を使わない」。
- 一方、Daily で勝っても結果画面に「報酬カードを選ぶ」は**表示される**（`GameOverOverlay.tsx:337` は mode を見ない／`BattleScreen.tsx:658` も同様）。つまり **Daily の報酬は通常モードの編成上限にだけ効く**。Daily プレイヤーには「もらったのに使えない」体験になる。

### 1-8. 難易度別差
- かんたん／ふつう／むずかしい・神階Ⅰ〜Ⅶのいずれでも**同じ提示・同じ効果**。難しい勝利ほど良い報酬、という設計は存在しない。

### 1-9. 「強いカードを取る」以外の選択意味
- 存在するのは「3 枚目を積みたいカードか」の 1 軸のみ。しかも提示 3 枚はデッキ内容と無関係なので、その 1 軸すら成立しない回が多い。「今回は見送る」は常に選べ、見送っても不利益は 0。

### 1-10. 3 択に実質的な迷いが生まれるか
- 迷いが生まれる条件（同程度に欲しいものが 2 つ以上）が、等確率抽選＋デッキ非参照では偶然にしか起きない。期待される典型回は「共通 3 枚、どれも 1 枚しか入れていない」＝全部ハズレ。

## 2. 価値の見積（定性的・simulation なし）

| 回の種類 | 発生率（概算） | 即時価値（おすすめデッキ運用） | 手動編成プレイヤー |
|---|---|---|---|
| 専用カードを含む 3 択（専用 2 枚積みの神：恵比寿・大耀・才華・福永） | ≈31% × 4/7 神 | 中（その専用を 3 枚目に） | 中 |
| 専用カードを含む 3 択（専用 1 枚積みの神：蒼毘・寿楽・笑蓮） | ≈31% × 3/7 神 | 0（2 枚目は報酬なしでも可） | 低 |
| 共通のみの 3 択 | ≈69% | **0** | 低〜中（2 枚積みしている共通があれば） |

→ 「勝利 1 回＝報酬の判断 1 回」（決定166）という儀式は整っているが、**判断の中身が空になりやすい**。

## 3. 良い点（維持すべきもの）
- 決定論（seed 付き）・`Math.random` 不使用・`src/core` 非依存・save version 分離（決定43 の設計品質は高い）。
- 「デッキ 20 枚・2 枚制限」というゲームの骨格を壊さない軽量メタ進行という方針自体は正しい。
- 結果画面で報酬だけを先に出す導線（決定166）は良い。

## 4. 根本原因（Root Cause）
1. **母集団の同一性**：報酬が「新しく手に入るもの」ではなく「既に持っているものの上限 +1」である。
2. **デッキ非参照**：3 択がプレイヤーの実デッキ・所持上限・神を見ていない。
3. **自動反映なし**：おすすめデッキ導線では効果がゼロ。
4. **Daily での提示**：効かないモードでも提示される。
5. **難易度非連動**：努力と報酬が比例しない。
