## 1. Executive Summary

**Decision：B. 49マス概念は採用するが、UI と条件を変更する（Confidence: Medium）**

**最重要質問「49 マスは『別の神でも攻略してみたい』を生むか」への答え：条件付きで YES。** ただし決定186 の「7×7 到達盤を戦績に置く」形のままでは NO に近い。根拠は 3 つ。

1. **戦い方の違いは『敵』ではなく『神』から生まれる。** シミュレーションで、同じ神のまま敵を替えたときの平均撃破ラウンドの差は **0.56〜0.67R**、同じ敵のまま神を替えたときは **0.74〜1.12R**。神の一撃の回数は神ごとに **0.37〜1.22 回／戦**（Optimizer、約 3.3 倍）と開きがある（§5）。つまり「この神で 7 敵を埋める」方向は同じ手触りの反復（＝作業）になりやすく、「この敵を別の神で倒す」方向が本当の変化を生む。
2. **通常戦の神×敵の履歴は存在しない。** `sevengods.records` は神ごとの集計のみで敵を持たない。神×敵が残っているのは `sevengods.daily`（神域挑戦・直近 30 日分）だけ（§3）。したがって新しい最小 storage が必要で、過去の通常戦の勝利は復元できない（§11・§12）。
3. **7×7 表は 390px で読めない。** 試作で 395px にはみ出し、敵の列見出しが 40px の絵だけになって判別できない。敵ごとの行に 7 柱の神チップを並べる形は、はみ出し 0・敵名 15px・神名 11px・チップ 45×49px で読める（§13・§14）。

**推奨設計（1 案）：**
- **1 マス＝「その神でその敵に 1 回勝つ」**。難易度・神階・神域挑戦かどうかを問わない（§6・§7）
- **見せ方は「敵ごとに、倒した神 k/7」**。戦績画面の先頭に「神×敵 攻略 N/49」節を置き、7 敵の行それぞれに 7 柱の神チップ（済み＝色＋金枠＋✓、未＝灰色＋✓なし）
- **選ぶ瞬間に出す**：敵選択カードに「この神で撃破済み ✓／未撃破」、神選択カードの自己ベスト行に「撃破 k/7 敵」
- **祝いは結果画面の 1 行だけ**：「✨ 初撃破：大耀 × 業斧の鬼将（鬼将 3/7 神）」。敵 7/7・神 7/7・49/49 のときだけ文言を差し替える。報酬・ポップアップ・通貨なし
- **Home と Next Goal には入れない**（P1 の情報量と優先順位を保つ。§10）
- **storage は新規キー `sevengods.matchups`（v1・additive）を 1 つだけ**。saveVersion・gameVersion は上げない。導入時に `sevengods.daily` の勝利だけを取り込み、それ以外は推測で埋めない（§11・§12）
- 既存不具合の修正を同梱：**戦績画面が 390px で横にはみ出す**（神域挑戦の表が 443px になりページ全体が広がる。Production で実測）

工数は決定186 の約 4 日に対し **約 4.0 人日**（妥当）。src/core 差分 0。

## 2. Strategic Goal

Phase 7 の Return Loop は「攻略 → 成長 → 収集 → 再攻略 → 比較」。P1 で「戦闘終了 → 結果理解 → 次の目標 → 次の行動」を作った（決定188 LIVE）。P2 が担うのは **収集 → 再攻略** の接続で、具体的には次の 1 文に集約する。

> **「この敵、まだ◯◯（別の神）では倒していない」と、敵を選ぶ瞬間に思えること。**

P2 の成功条件は「49 マスが埋まること」ではなく、**使う神が偏っていたプレイヤーが、自分から別の神を選ぶ回数が増えること**。49 という数字はその結果の可視化にすぎない。

## 5. Player Value

### 5-1. 組み合わせの差（決定186 シミュレーションの再集計）

7 神×7 敵、各組み合わせ 24 戦（勝利時）の平均撃破ラウンド：

| タイプ | 組み合わせ平均の範囲 | 同じ神で敵を替えた差（7 神平均） | 同じ敵で神を替えた差（7 敵平均） |
|---|---|---|---|
| New | 4.38〜5.79R | 0.67R | 0.74R |
| Casual | 3.71〜5.29R | 0.56R | **1.12R** |
| Optimizer | 3.42〜4.96R | 0.60R | **1.03R** |

神の一撃（共鳴バースト）の回数／戦（Optimizer）：才華 1.22、恵比寿 0.84、大耀 0.79、福永 0.77、寿楽 0.68、笑蓮 0.49、蒼毘 0.37。
勝率はいずれの組み合わせも 100%（ふつう・AI）。組み合わせの平均スコア差も 901〜1,022（Optimizer）で小さい。

**読み取り**：敵の違いは「型の予告（重撃・連撃・溜め など）」という読み合いの差としては存在するが、結果の数字にはほとんど表れない。**手触りの差を最も大きく生むのは神の選択**。49 マスは「神を替える理由」として設計すべきで、「1 柱で 7 敵を埋める」表現は作業感を強める。

### 5-2. 評価（決定186 の 7×7 案そのまま／推奨案）

| 項目 | 7×7 到達盤（そのまま） | 推奨（敵ごとの神チップ＋選択画面の印） | 根拠 |
|---|---|---|---|
| Player Value | Medium | **Medium-High** | 敵軸という新しい情報は価値があるが、戦績画面の奥だけでは見られない。選択画面に出すと毎戦目に入る |
| Replay Motivation | Low-Medium | **Medium** | §5-1 のとおり神の差が大きい。「この敵を別の神で」は本当に違う 1 戦になる |
| Collection Motivation | Medium | **Medium** | 有限・明確（49）。ただし報酬を付けないので強制力は弱い（意図どおり） |
| Strategic Variety | Low | **Medium** | 神の切替を促す表現なら、神の一撃 0.37〜1.22 回の違いを体験させられる |
| Comprehension | Medium（SP で敵が判別不能） | **High** | 「勝つと点灯」1 条件、敵名が読める |
| Implementation Cost | Medium | **Medium** | 新規 storage 1＋戦績節＋選択画面の印＋結果 1 行（§19：約 4.0 人日） |
| Storage Cost | Low | **Low** | 神ごとの撃破済み敵 ID 配列（最大 49 要素） |
| Save Compatibility | High | **High** | 新規キーのみ・saveVersion 不変・旧ビルドは無視（§11） |
| Balance Risk | None | **None** | 戦闘・スコア・報酬に一切影響しない表示と記録のみ |
| **Grind Risk** | **Medium-High** | **Medium** | 下記 |

**Grind Risk（厳しく評価）**：
- 49 マスは 49 勝で必ず埋まる（抽選・周回・確率なし）。有限で終わりが見えるのは作業感を抑える要素
- 一方、1 マス＝1 勝で、ふつうの勝率が高い（AI 100%）ため、**1 マスごとの達成感は薄い**。ここに報酬や Home の催促を足すと「埋めなければならない作業」になる → **報酬なし・Home に出さない・Next Goal で催促しない** を必須条件にする
- 敵の選び方で負担が大きく変わる：「神に委ねる」（ランダム）だけで 49 マスを埋める期待値は **約 127 戦**（1 神あたり 7×H₇≒18.2 戦）、狙って選べば **49 戦**。**敵選択カードに「この神で撃破済み／未撃破」を出すことが、作業量を約 2.6 分の 1 にする最重要部品**
- 1 戦 5 分前後と見て、狙って埋めても約 4 時間。コンプリートは任意の長期目標として適切な規模で、上限を増やす（難易度別・神階別のマス）ことはしない（§7）

## 6. Completion Rule（1 マスが埋まる条件）

| 候補 | 1 秒で分かるか | 評価 |
|---|---|---|
| **A. その神でその敵を 1 回撃破** | **分かる**（「勝てば点灯」） | **採用** |
| B. ふつう以上で撃破 | 条件の説明が要る（「かんたんは対象外」） | 却下：かんたんで遊ぶ New Player の勝利を記録しないのは逆効果。ふつうでも AI 勝率 100% で難度の意味が薄い |
| C. 最高神階到達 | 分からない（神ごとの段と混ざる） | 却下：神階は神ごとの長期目標としてすでに存在（決定126） |
| D. 自己ベスト記録 | 分からない（何点なら埋まる？） | 却下：比較対象が無く条件にならない |
| E. 複数段階（撃破→速攻→無傷…） | 分からない | 却下：P2 の禁止事項（複雑化） |

**採用：「その神でその敵に 1 回勝つ」**。
- 通常戦・神域挑戦のどちらの勝利も数える（神域挑戦は神域強化で難しくなっているだけで、その神がその敵を倒した事実に変わりはない。スコアを通常の自己ベストに混ぜない CEO 決定5 とは別の話＝点灯はスコアではない）
- 敗北・未撃破（7R 終了）は数えない
- 途中放棄・中断は数えない（決着した勝利のみ）
- 1 回点灯したら消えない（同じ組み合わせの再勝利は何も起きない）

画面の説明文（1 行）：「その神でその敵に 1 回勝つと点灯（難易度・神階・神域挑戦を問いません）」

## 7. Difficulty / Stake

同じ神×敵にも難易度 3 段と神階 Ⅰ〜Ⅶ がある。これをマスに載せると **49×(3＋7)＝490 項目**、少なくとも 49×3＝147 項目のチェックリストになり、P2 の目的（神を替える理由）と逆行する。

**決定：49 マスは「撃破の有無」だけを表す。難易度と神階はマスに載せない。**

| 情報 | 置き場所（既存・変更なし） |
|---|---|
| 難易度 | 戦績の神カード「自己ベスト N（むずかしい）」 |
| 神階 | 戦績の神カード「神階 最高到達」、神階選択、Home 進行チップ |
| 神技評価 | 結果画面 |

補助表示もしない（マスの中に難易度の印や段の数字を入れない）。将来「むずかしいで撃破」などの上位印を検討する場合は、P2 の実データ（使う神の偏りが変わったか）を見てから別 Step で判断する。**記録側も難易度・神階は保存しない**（使わない情報を保存しない）。

## 11. Storage

### 11-1. 既存 storage で保持できるか
- `sevengods.records`：神ごとの集計で、敵の次元が無い。`GodRecord` に配列を足す案は可能だが、**通常モードでしか書かれない**（`recordGameResult` は Daily で呼ばれない＝CEO 決定5）ため、神域挑戦の勝利を点灯させるには Daily 側にも書き込みを増やす必要がある。さらに records は戦績・神選択・神階解放判定（`isStakeUnlocked`）が読む中核データで、壊したときの影響が大きい
- `sevengods.daily`：30 日で消える（`prune`）。永続記録にならない
- → **既存キーに相乗りせず、新規キーを 1 つだけ追加する**

### 11-2. 最小 additive schema

```ts
// key: 'sevengods.matchups'（hooks 層・独立 version＝不変ルール5・既存 storage と同じ流儀）
type MatchupData = {
  version: 1
  /** godId → その神で 1 回以上撃破した敵 ID（重複なし・順不同） */
  cleared: Partial<Record<GodId, EnemyId[]>>
  /** 導入時の取り込み（§12）。いつ・何から作ったかを残す（監査用。UI は日付だけ使う） */
  seeded: { at: number; source: 'daily' }
}
```

- 書き込み：`useGameEngine` の決着処理（`status === 'won'` の瞬間、通常・神域挑戦の両ブランチ）で `recordMatchupClear(state)` を 1 回呼ぶ。戻り値 `{ isFirstClear, godClearedCount, enemyClearedCount, totalCleared }` を結果画面の 1 行に使う
- **冪等**：集合への追加なので、再開・再描画・同じ組み合わせの再勝利で二重に数えない
- 読み取り：戦績画面、神選択カード、敵選択カード
- 検証：`version !== 1` や構造不正は空として扱う（既存 storage と同じ try/catch＋構造チェック）。未知の godId／enemyId は読み飛ばす
- `localStorage` が使えない環境：記録されないだけでゲームは止めない

### 11-3. 版と互換
| 項目 | 判定 | 理由 |
|---|---|---|
| saveVersion（9） | **上げない** | 進行中セーブ（`battleSave`）と `deckPreference` の形は変えない |
| gameVersion（`1.80c6eda23ed082dc`） | **上げない** | 指紋はランキングに影響するデータ（調整値・カード・敵・神・OTOMO・神託）のみ。P2 は表示と端末内の記録だけ |
| 既存 records／daily／stakes／bond | 変更なし | 新キーのみ |
| 旧ユーザー | 互換 | 新キーが無ければ §12 の取り込みで作る |
| ロールバック（P1 ビルドへ戻した場合） | 安全 | 旧ビルドは `sevengods.matchups` を読まず、書き換えもしない |
| Daily 公平性 | 不変 | Daily の GameState・seed・回数・日付切替に一切触れない（勝利後に記録するだけ） |
| Ranking | 不変 | 送信 payload・`submissionEnabled` に触れない |

## 12. Historical Backfill

**取り込めるもの（事実のみ）**：`sevengods.daily.days[*].results[*]` のうち `status === 'won'` の `(godId, day.enemyId)`。保存期間は日付キー 30 件まで（プレイした日の数で数える）。

**取り込めないもの**：通常戦の過去の勝利。`records.wins` は神ごとの勝利数で、どの敵に勝ったか分からない。**勝利数から点灯を推測しない**（例：「大耀 14 勝なら少なくとも 1 体は」も埋めない）。

**方法**：
1. `sevengods.matchups` が存在しないときに 1 回だけ実行（読み込み時の初期化）
2. `sevengods.daily` の勝利結果から `cleared` を作り、`seeded = { at: 導入時刻, source: 'daily' }` と共に保存
3. 以後は決着時の記録だけで増える（再取り込みはしない。30 日で消える Daily に依存しないため）

**影響の評価**：
- 導入直後、通常戦を多く遊んだプレイヤーほど「勝ったはずの組み合わせが暗い」状態になる。これは避けられない
- 緩和策（表示のみ）：戦績の節の説明に 1 行「この表は YYYY-MM-DD 以降の勝利と、神域挑戦の直近の勝利から作られています」（`seeded.at` の JST 日付）。既存の神カード（勝利数・自己ベスト・神階）はそのまま残すので、過去の実績が消えたようには見せない
- 1 マス＝1 勝なので、取り戻す負担は小さい（狙えば 1 戦で 1 マス）

## 15. Commercial Principles

商用ゲームのコレクション・到達表示から、SEVEN GODS に必要な原則だけを抽出した（機能のコピーはしない。存在するという理由だけで足さない）。

| 原則 | 一般的な形 | SEVEN GODS への適用 |
|---|---|---|
| **progress visibility は選ぶ瞬間に** | キャラクターや難易度を選ぶ画面に、そのキャラで到達済みの印を出す（ローグライト系で広く見られる） | 敵選択カードの「撃破済み／未撃破」、神選択カードの「撃破 k/7 敵」 |

| **義務化を避ける** | デイリー・期限・報酬と結びついたコレクションは作業化しやすい | Home・Next Goal に出さない、報酬を付けない |

## 20. Final Recommendation

**B. 49 マス概念は採用するが、UI と条件を変更する（Confidence: Medium）**

- 49 の「神×敵の撃破」という概念は採用する。条件は「その神でその敵に 1 回勝つ」だけにする
- 見せ方は 7×7 表ではなく **敵ごとの行に 7 柱の神チップ**（SP で読める・§5-1 の「神を替えると本当に変わる」軸を前に出す）
- 情報は **選ぶ瞬間（敵選択・神選択）と、勝った瞬間（結果の 1 行）と、戦績** にだけ出す。Home と Next Goal には入れない
- storage は新規キー 1 つ（additive・saveVersion／gameVersion 不変）。過去分は神域挑戦の勝利だけを取り込み、通常戦の過去は推測しない
- 既存不具合（戦績画面の SP 横はみ出し）を同梱修正する
- Confidence を High にしない理由：49 マスが実際に「使う神の偏り」を変えるかは、端末内の記録しか無いこのゲームでは事前に測れない（シミュレーションで分かるのは組み合わせの差だけ）。CEO 実機 QA で「別の神を選びたくなるか」を確認項目にする

次の一歩：本仕様に基づく **Phase 7 P2 実装**（別 Step）。着手前の CEO 確認事項は無い（§6-2 範囲。storage 追加は additive で saveVersion 不変）。
