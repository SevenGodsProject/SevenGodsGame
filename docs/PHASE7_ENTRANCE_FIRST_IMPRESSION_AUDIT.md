## 1. Executive Summary

**最終判定：B. GO WITH MODIFICATIONS（Entrance を P3 より先に、ただし最小の E1 だけを実装する）／Confidence：Medium**

仮説「ゲームに入った瞬間の商用品質が弱い」は**実測で支持された**。Entrance の現状スコアは **44 / 100**。戦闘画面は全面シーン＋キャラ＋カードで「ゲーム」に見えるが、そこへ至る入口はテキスト列と枠とボタンで構成され、「Web アプリの機能選択」に見える。特に弱いのは次の 5 点。

1. **新規プレイヤーの最初の 3 秒は「699 字の説明書モーダル」**。Home は暗転してその下に隠れ、閉じるボタン「わかった」は 4 画面すべてでモーダル内を 1.4〜1.9 画面ぶんスクロールしないと見えない【実測】
2. **スマホの Home には神がいない**。初期 viewport に占める神の画像は、新規で 11.7〜18.7%（下端に切れて見える程度）、復帰プレイヤー（続きあり）では **0〜7.4%**【実測】。IP の中心である七神が、最も多い利用形態で第一画面に登場しない
3. **Home の神は常に恵比寿で、プレイヤーが使っている神を反映しない**（`HomeScreen.tsx` の `FEATURED_GOD = GODS[0]`）。「大耀 vs 業斧の鬼将」の続きがあっても絵は恵比寿。敵と OTOMO の Home 上の画像占有率は 0%【実測】
4. **Primary CTA が小さく、メニューの言葉**。PC の「神を選ぶ」は 128×52px＝viewport の 0.7%。すぐ下の Today パネルの CTA（169×44px・金枠）のほうが大きく、金色の CTA が 2 つ競合する【実測】。文言は「神を選ぶ」＝設定手順の名前で、世界の中の行動ではない
5. **初戦までの摩擦が商用水準の 2〜7 倍**。新規は URL を開いてから最初のカードまで **7 クリック・6 画面遷移**、うち 3 クリックはスクロールが必要、途中で読める説明文は合計 **約 4,200 字**【実測】。MARVEL SNAP は説明より先に実戦へ直行する【出典】

一方、**復帰導線は P1 によって既に商用水準**（続きから＝1 クリック・1.1〜3.1 秒で戦闘【実測】、Today が第一画面内）。ここは壊さず、土台として使う。

修正点（仮説をそのまま採らない部分）は 3 つ。①Home を言葉で「神域」と呼ばない（「神域」は既に Daily＝神域挑戦を指す語で、二重の意味になる）。見た目で神域にする。②2〜3 秒の強制 Splash は採らない。セッション初回だけの「タップで入る」タイトル（音の解錠を兼ねる）を E2 の条件付き案とする。③初回プレイヤーの一本道化・機能ロックはしない。「初陣」という近道を Primary に置くだけで、全選択肢は Secondary に残す。

E1 は display-only（`src/core` 差分 0・storage 書き込み 0・新規 key 0・新規アート 0）で成立する見込みで、期待スコアは **62〜70 / 100**（予測）。

### 4-3. SEVEN GODS へ転用できる原理

1. **説明しないキービジュアル**：顔のアップにモチーフを 1 つ添え、文字で説明しない。→ 神の顔・上半身を第一画面の主役にする
2. **画面の型を固定する**：タイトル＋1 行の副題＋主 CTA 1 つ。→ Home・神選択・敵選択・Daily で同じ型
3. **絵を背景として全面に敷き、UI は半透明パネルを重ねる**：SEVEN GODS の戦闘画面は既にこの作り。入口だけがこの作りになっていない
4. **配色を絞る**：現行の濃紺＋金は近い位置にいる。Today パネルの紫と、下線付きリンクの白が混ざって弱めている
5. **メニュー名は世界の中の行為に。ただし誤解されやすい語は平易なまま残す**
6. **主 CTA は 1 つだけ金、他は金にしない**
7. **案内役の常駐と 1 行の助言**：SEVEN GODS には OTOMO がいる。Home での OTOMO の占有率は現在 0%
8. **起動直後に「すでに何かが起きている」画面**：SEVEN GODS では「今日の敵がそこに立っている」で代替できる

### 4-4. 転用すべきでないもの

1. 固有の用語（御霊・忍務・浄夜・番付・栞など）、雲文様の飾り枠、月蝕のモチーフ、キャラクターデザインと立ち絵の構図
2. 8 タブの常時表示（1 戦完結のカードバトラーには多すぎる。SEVEN GODS の Home は既にボタンが多い）
3. 放置・ガチャ・トークン報酬を前提にした誘因（SSR 確定、連数の訴求）。SEVEN GODS は課金・ガチャを持たない
4. 先に長い物語を読ませてから遊ばせる順序（公式の初日手順は「序の道行きを終幕まで」が先頭【出典 S2】）。SEVEN GODS は 1 戦 3〜5 分のスコアアタックで、**まず 1 戦させる**のが正しい
5. 時間経過での機能解禁（3 分後に店、7 分後に装備【出典 S2】）。セッションが短い Web ゲームには合わない
6. AI 会話・フルボイス前提の演出コスト

## 13. Splash Hypothesis

**結論：条件付き必要（E2。E1 には含めない）**

| 場面 | 評価 |
|---|---|
| 初回 | 有効。ロゴ演出は「入ってきた感じ」を作り、LCP 画像（511KB。回線を絞ると 6.0 秒【実測】）の読み込みを隠せる |
| 通常起動・再訪 | **時間で待たせる Splash は不要**。復帰プレイヤーの強みは「続きから 1 クリック・1〜3 秒」で、2〜3 秒の強制演出はこれを 2 倍に遅くする |
| スマホ／ブラウザ | **「タップで入る」タイトルには機能上の意味がある**。現状、BGM は最初のタップまで鳴らない（`bgm.ts`）。タイトルのタップが音の解錠になり、Home に音つきで入れる。これは Web ゲーム固有の利点 |
| PWA | 現状 PWA の manifest は未確認・対象外。検討は E2 で |

採るなら次の条件をすべて満たすこと。

- **セッション初回のみ**（`sessionStorage`。Result → Home や画面内の戻りでは出さない。永続 storage の新規 key は作らない）
- **待たせない**：演出は最大 1.2 秒。演出中でも**いつでもタップで即 Home**。自動では進めず「タップで入る」（音の解錠のため）
- `prefers-reduced-motion` では静止画 1 枚（既存の `reducedMotion.ts` の方針を流用）
- 演出は既存素材のみ（七つの光＝CSS、ロゴ＝テキスト、コピー＝既存のタグライン「七柱の神と挑む、七日間の物語。」）
- 自動 QA（P1／P2／Hardening の acceptance、`qa-flow.mjs`）はすべて `.home-screen` の出現を待つ作りのため、Splash を入れると全スクリプトに影響する。**これが E1 に含めない主な理由**

毎回 2〜3 秒の強制 Splash は **NO-GO**。

## 14. First-Time Player

**結論：必要。ただし一本道化・機能ロックはしない。「初陣」という近道を Primary に置くだけ**

現状の確認：

- 初回は遊び方モーダルが自動で開く。閉じると `sevengods.tutorialSeen` を保存（`tutorialStorage`）。以後は開かない
- モーダルを閉じた後の新規プレイヤーには、7 神・3 難易度・8 敵・デッキ編成（1,694 字）の全選択肢が一度に来る（§8）
- 遊び方の第 1 節自身が「最初は『おすすめデッキ』のままで大丈夫です」と書いている。つまり**既定値で始めてよいと設計側が認めているのに、既定値で始める経路が無い**
- `GameFlow.tsx` は既に `getRecommendedDeck` を import しており、`engine.startGame` に神・デッキ・敵・難易度を渡せば即開始できる。新しい engine 機能は不要

推奨（1 案）：

1. 初回（戦績 0 かつ `tutorialSeen` なし）の Home の Primary を「**初陣へ**」（副題「おすすめの構成ですぐ戦う」）にする。Secondary に「神を選ぶ」を残す（全選択肢へ行ける）
2. 「初陣へ」は **神 1 柱・おすすめデッキ・試練の影（脅威度★1・標準／入門型）・難易度「ふつう」** で即開始
3. 初陣の神は**恵比寿を第一候補**とする。理由：Home の主役の絵（唯一の高画質版）と初戦の神が一致する／神選択の説明が「扱いやすい速攻型」／`GODS[0]`。ただし**最終決定は Minimal Spec で `balanceSim` を回し、初戦の勝率と所要ラウンドで恵比寿と大耀を比べてから**（勝率が 70% を下回るなら難易度を「かんたん」にする）
4. 遊び方モーダルは**起動時に自動で開かない**。「初陣へ」を押した時に、3 行の短縮版（予告を見る／神力の範囲でカードを出す／ラウンドを終える）を出し、「わかった」をスクロールなしで押せるようにする。6 節の完全版は現行どおりヘッダーと Home のリンクから開ける
5. 初戦の後は、既存の Result Hub（P1）の Next Goal／別アクティビティ CTA が 7 神・神域挑戦・戦績を紹介する。**新しい解放システムは作らない**
6. 期待値：7 クリック → **3 クリック**（初陣へ → わかった → カード）。60 秒目標の内訳は、ロード 3 秒＋Home 5 秒＋短縮版 15 秒＋Boss Entrance 1.4〜2.8 秒【実測】＋最初のカード 10 秒＝**約 35〜40 秒**【推測】。「60 秒以内に最初のカード」は妥当な受入基準

採らないもの：7 神やデッキ編成のロック（既存プレイヤーの保存と整合を取る仕組みが要り、storage 変更になる）、強制チュートリアル戦（engine の縮小盤面が要る＝`src/core` 変更）。戦闘中の状況コーチ（過去監査 §12 の 3 例）は有効だが Entrance の範囲外。

- 神×敵攻略（`matchupStorage`・`MatchupBoard`）、選択画面の印、初撃破の 1 行は Home と独立。E1 は触れない

### P3（競合しない）

- 決定192 の Known Risk（`otomo.defId` の未知 ID 耐性）は E1 と独立。E1 は OTOMO を Home に描かない（描く場合は `enemyLookup.ts` と同じ安全な参照を先に用意する）ため、リスクを増やさない

- 触らない：`src/core`、`src/hooks/useGameEngine.ts`、storage の schema、Score／Seed／Daily 回数、cards、enemy／god／OTOMO の定義、Ranking、Neon、DB

### New Assets：**条件付き**

- 新規アートは**不要**。神 7 柱のキービジュアル、敵アート、ステージ背景は揃っている
- 条件：恵比寿以外の 6 柱は軽量版（675×900）しか配信していない。Home の全面表示で DPR 2 以上の端末だと粗く見える可能性がある。その場合は、既存の原本（`art-source/reference/gods/*-keyvisual.png`）から**非生成の再エンコード**で高画質版を 6 枚作る（恵比寿の `keyvisual-hero.webp` と同じ手順）。読み込むのは選択中の 1 枚だけにする（7 枚で約 3.5MB を一度に取らない）

### Risks

| リスク | 影響 | 対策 |
|---|---|---|
| P1／P2 の acceptance が Home の構造に依存 | QA の取り直し | testid と文言「神を選ぶ」「続きから」を維持。基準の取り直しは E1 の gate に含める |

| 効果を数字で確かめられない | 判断の確度 | 実ユーザーの計測基盤が無い。E1 の効果は同じ計測スクリプトの再測定と CEO QA で確認する。流入・離脱の計測は別途の判断事項（個人情報・外部サービスに関わるため §6-3 に該当しうる） |

## 22. Final Decision

**B. GO WITH MODIFICATIONS — Entrance を P3 より先に実装する。ただし E1（最小）のみ**

- **Confidence：Medium**
  - 高い部分：問題の存在と場所は Production の実測とコードで確定している（SP の第一画面に神がいない、7 クリック、699 字のモーダル、固定の恵比寿、CTA の競合）。E1 が display-only で済むこともコードで確認した
  - 中程度にとどまる理由：①実ユーザーの流入・離脱データが無く、効果は予測。②競合のタップ数は大半が推測で、実機未計測。③重点対象の月蝕綺譚が未配信で、タイトル画面と初回フローを確認できていない。④期待スコアは AI の採点による予測
- 修正点：Home を言葉で「神域」と呼ばない／強制 Splash は採らず、タップで入るタイトルを E2 の条件付き案に／新規の一本道化・機能ロックはしない／Primary は状態で 1 つ
- **実装は開始していない**。次の工程は「Entrance E1 Minimal Specification」（仕様化のみ。`balanceSim` による初陣の神・難易度の決定、Home の rect 目標値、acceptance script の設計、P1／P2 の基準取り直しの範囲を確定する）

### 付録 0 — Errata／E1 Minimal Spec での精緻化（2026-09-17 追記）

`docs/PHASE7_ENTRANCE_E1_MINIMAL_SPEC.md` の作成時に本書を再検証した。実測値・コード参照・競合の出典に誤りは見つからなかった。次の 4 点は**本書の記述が不正確または粗かった**ため、Spec 側の内容を正とする。

1. **§19-1／19-2 の構図**：本書は「今日の敵のステージ背景を全面に敷き、その上に神を枠なしで置く」と書いたが、神のキービジュアル（`keyvisual.webp` 675×900、原本 1086×1448 ほか）は**背景込みの矩形イラストで、切り抜き（透過）ではない**。ステージ背景の上に神だけを重ねることは既存素材ではできない。透過なのは敵アート（768×768・alpha あり）。Spec では「神のキービジュアルそのものを全面の場面として使い、敵の切り抜きを『今日の試練』として小さく重ねる」構図に改めた（ステージ背景は Home では使わない＝転送量も増えない）
2. **§12 の Primary の表「Daily に回数が残っている → 神域へ挑む」**：P1 の Next Goal（N4）は「今日の神域挑戦が**まだ手つかず**（`attemptsUsed === 0`）」の時だけ Daily を勧める。Spec ではこれに揃え、1 回以上挑戦済みの日は通常攻略（神を選ぶ）を Primary にする（Daily を強制しない）
3. **§14 の「初回」の条件「戦績 0 かつ `tutorialSeen` なし」**：Spec では `tutorialSeen` を条件から外し、「プレイの痕跡が無い」（続きなし・全神の戦績 0・Daily の履歴なし・`deckPreference` なし）だけで判定する。初陣の神は `balanceSim` で 7 神を比較し**恵比寿・難易度「ふつう」に確定**した
4. **§2-2 の回線制限時の LCP 6.0 秒**は 1 回の計測値。Spec で 3 回×2 条件を取り直し、中央値は新規 5.8 秒／復帰 6.1 秒（範囲 5.5〜7.7 秒）、CLS 0。結論は変わらない。LCP は「恵比寿の高画質版 511KB のダウンロード完了時刻」とほぼ一致する

また §21 の「Home の下位リンク 3 本」は、Spec で「遊び方を見る」をヘッダーの既存アイコンに一本化し 2 本にした（操作要素の上限 5 個を満たすため。機能の削除ではない）。
