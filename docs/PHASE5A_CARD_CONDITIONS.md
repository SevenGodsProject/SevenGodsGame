## 4. シミュレーション結果と、未達2件の原因

### 4-1. STAKE-01（基準 #2・#3）→ FAIL

| 神階 | 実装前 | 実装後 | 差 |
|---|---|---|---|
| Ⅰ | 89% | 93% | +4 |
| Ⅱ | 86% | 92% | +6 |
| Ⅲ | 79% | 90% | +11 |
| Ⅳ | 73% | 86% | +13 |
| Ⅴ | 67% | 82% | +15 |
| Ⅵ | 62% | 76% | +14 |
| **Ⅶ** | **49%** | **67%** | **+18** |

`balanceSim` の床（Ⅰ55%…Ⅶ10%）と単調性のアサーションは**両方とも通っている**。
外れたのは決定153 で自ら置いた ±5pt の目標値と、決定126 の設計ターゲット（Ⅶ 25〜35%）である。

**原因の分解**（`P5A_SWEEP=1`。同じ harness で成分だけ入れ替えた）：

| 変種 | 神階Ⅶ |
|---|---|
| 追加効果を全部消す（基準線） | **53%** |
| 現在の実装 | **71%** |
| 火力/防御/回復の追加だけ（テンポ系を消す） | 62%（+9pt） |
| テンポ系（共鳴・ドロー・神力）の追加だけ | 65%（+12pt） |
| 火力/防御/回復を**半分**にする | **71%（変化なし）** |

読み取れること：

1. **量ではない。** damage/block/heal を半分にしても Ⅶ は 71% のまま動かない。
2. 効いているのは**テンポ系**（共鳴+1・ドロー+1・神力+1）で、共鳴が早く回る＝
   神の一撃（敵HPの2〜3割）が1回多く出ることが効いている。
3. つまり「16枚の**最もよく使う共通カード**に、下振れの無い純増を足す」設計そのものが、
   固定方策の勝率を必ず押し上げる。**±5pt と「意味のある追加効果」は同時に成立しない。**

これを ±5pt に収めるには、次のどちらかが要る。どちらも Phase 5-A の禁止事項に触れる：

* (A) **本体の数値を下げ、条件成立で元に戻す**（＝平均を動かさない）。CEO 指示「基礎数値は原則変更しない」に抵触
* (B) **神階ラダーか敵の数値を締め直す**（決定126 の難易度設計に手を入れる）

→ **どちらもやらずに、事実として報告する**（§7 の CEO 判断事項）。

### 4-2. cardpref の神別の幅（基準 #4）→ FAIL

Phase 3 と同じ harness（探索AI × ランダムデッキ × `DECKS=300` × C0）で、実装前後を同一セッションで比較：

| 条件 | 指標 | 実装前 | 実装後 |
|---|---|---|---|
| stake5 | ラウンド最初のカードの attack 比率スプレッド | 7.5pt | **7.0pt** |
| stake5 | 種別スプレッド合計 | 29.5pt | 30.2pt |
| stress | attack 比率スプレッド | 12.7pt | 10.0pt |

**広がらなかった。** 理由は単純で、**強くしたのが7神すべてが共有する共通カードだから**。
共有プールの価値が上がると、神ごとの打ち筋はむしろ**似る**。
決定153 の「共通カードに条件を足せば神差が広がる」という仮説は、測定で否定された。

ただし、**神ごとに「どの条件で戦うか」ははっきり分かれた**（`P5A_RUN=1`・aware・ふつう・392戦）：

| 神 | 条件の内訳（回/戦） |
|---|---|
| 蒼毘 | **blocked 1.57**・enemyBig 1.05・combo 1.52・charged 0.32 |
| 才華 | **combo 2.36**・**charged 0.84**・blocked 1.34 |
| 寿楽 | enemyBig 1.30・combo 1.54・**blocked 0.00** |
| 恵比寿 | combo 2.30・charged 0.61・blocked 0.64 |
| 笑蓮 | blocked 1.18・enemyBig 0.63・lowHp 0.02 |

蒼毘は「予告を受け切って反撃する神」、才華は「並べて回す神」、寿楽は「大技を待つ神」という
プレイ感の差が数値に出ている。#4 が測ろうとした「神差」は**別の軸には確かに現れた**が、
基準として置いた指標では出なかった。基準は未達のまま扱う。

### 4-3. 成立頻度・判断の発生（基準 #5・#6）

| 指標 | blind（条件を意識しない） | aware（条件を狙う）ふつう | aware むずかしい |
|---|---|---|---|
| bonus 成立 | 2.55回/戦 | **3.70回/戦** | **4.23回/戦** |
| 選択が変わった回数 | 3.17回/戦 | **2.29回/戦** | 2.33回/戦 |
| 平均ラウンド | 5.11R | 5.00R | 5.39R |

条件別（aware・ふつう）：combo 1.75 / blocked 0.94 / enemyBig 0.61 / charged 0.40。
**4条件すべてが実際に成立している**（どれか1つに偏っていない）。

#5 はふつうで 3.70 と基準の4をわずかに下回る。むずかしいでは 4.23 で満たす。
実プレイの人間は blind と aware の間に来るため、**「ふつうでは基準にわずかに届かない」と扱う**。

## 5. 互換性

### 5-1. セーブデータ

`GameState` の構造は**変えていない**（`cardsPlayedThisRound` も `resonance` も既存フィールド）。
`saveVersion` は **9 のまま**。旧セーブはそのまま読める。

### 5-2. Daily / ランキング

`gameVersion` は **`1.da595899c6a9db43` → `1.b783d71956fe9327`**（カードデータが変わったので
`dataFingerprint` が自動で拾った）。`engineVersion` は **1 のまま**でよい：
新条件の評価器はデータ（`bonus.when`）が指すときにしか働かず、挙動の変化はすべてデータ由来のため。

**deploy するなら JST 0:00 直後**。日中に版が変わると、その日の Daily は day-lock により
新規 start が 423 で止まる（既存仕様どおり。進行中 run は voided で枠が返る）。

### 5-3. golden replay

固定リプレイは**入力ごと作り直した**。カードの効きが変わると、以前の操作列は
「敵が早く倒れて、そのあとの END_ROUND が拒否される」形で**再生できなくなる**ため
（結果の比較以前の問題）。再生成は `scripts/phase5a-cards/cardsAudit.test.ts`（`P5A_GOLDEN=1`）。

## 6. 実プレイQA（localhost・2026-09-11）

| # | 構成 | 結果 |
|---|---|---|
| 1 | 恵比寿 × 試練の影 × ふつう × おすすめデッキ | **勝利 R6 / 8,030点** |
| 2 | 蒼毘 × 双牙の魔獣 × むずかしい × おすすめデッキ | R2 まで（検証機の描画停滞で中断） |
| 3 | 恵比寿 / 才華 × 390px 縦画面（モバイル確認） | 表示・操作とも問題なし |

**見えたこと**

* **R1 から判断が増えた。** 予告50・AP2 の初手で「見切り(1AP)→一撃(1AP)」と置くと、
  一撃が ⚡ になり **50 → 80ダメージ**。戦闘ログに「「一撃」の追加効果（2枚目以降）」と出る。
  実装前は「一番強い札を出す」以外の手が無かった場所である。
* **順番を考えるようになる。** 受け流し（共鳴+1）を先に置くと一撃が ⚡ に変わるのが画面で分かる。
  共鳴4に到達した瞬間、剛撃が ⚡ になり「今撃つか、もう1枚溜めるか」が発生した。
* **予告を見る理由が増えた。** 鉄壁の構え（ブロック120）は予告50に対して ⚡ が点き、
  「受け切れる量を積むと回復も付く」ため、予告の数字を読む動機になる。
* **弱いカードを先に切る価値がある。** 見切り・共振・受け流しといった単体では地味な1APが、
  「次の札を強くするための1手」になった。
* **別構成を試したくなるか**：条件の内訳が神で分かれる（§4-2）ため、
  「蒼毘で受け切る」「才華で並べる」は別のゲームに感じられた。ただし**共通カードが強くなった分、
  どの神でも同じ共通札が有力**という副作用もあり、動機としては半分の達成にとどまる。

**モバイル（390px）**：⚡ の行は琥珀色、＋ の行は灰色で、2枚並びのカード上でも判別できた。
横あふれ 0。デッキ構築画面は盤面が無いので常に ＋ 表記（3画面で表記が統一されている）。
