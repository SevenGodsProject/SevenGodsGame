## 1. 現在の根本原因

1. `.battle` は単純な縦積みで、**ページ全体がスクロール**する（doc 高さ：PC 1,570px／390px 2,356px）。
2. アリーナ（`.battle-main`）が **702px** 固定的に高い（敵パネル 682px：名前・型・吹き出し・立ち絵 300・HP・予告・バフ）。
3. 手札は **939〜1182px** の位置。カード自体が **244px** と高い。
4. その結果、**「敵が見える位置」と「カードを触れる位置」が排他**になる。
5. さらに PC 幅では「ラウンドを終える」が `position: fixed`（決定77）で、**カードの上に重なる**（実測で重なり＝あり）。
6. Phase 6-A で作った着弾・撃破の演出は**敵ポートレートの上**で起きるため、④の排他がそのまま「Combat Juice が見えない」になる。

## 5. 採用する1案：**Battle Viewport Layout**（D系。AIの決定）

```
┌──────────────────────────────── 上部バー（ラウンド／神力／スコア） 48
│ ┌──────────── アリーナ（残りの高さ・可変） ─────────────┐
│ │  [敵名札：名前 / HPバー / 予告20px / 状態]            │
│ │  [敵立ち絵：残り高さに収まる可変サイズ]   [神名札]     │
│ │                                          [神立ち絵]   │
│ │                                          [共鳴・OTOMO]│
│ └───────────────────────────────────────────────────────┘
│ [託宣バー：加護 / 導き / 天啓（横1列・44px）]
│ [手札ドック：カード5枚（164px）            ラウンドを終える]
└────────────────────────────────────────────────────────────
```

**設計の要点**

1. `.battle` を**画面の高さに収まる grid**（`grid-template-rows: auto minmax(0,1fr) auto auto`）にする。ページ自体はスクロールしない（`overflow: hidden`）。
2. アリーナは `1fr`＝**残りの高さ**。中の立ち絵は **`flex:1; min-height:0` の領域に収まる可変サイズ**（`background-size: contain` / `object-fit: contain`）。→ どの画面高でも**切れない・重ならない**。
3. 操作（託宣・手札・ラウンド終了）は grid の行として**場所を確保**する。`position: fixed` で重ねない（B/C の失敗理由）。
4. 敵・味方の情報は**名札**（名前／HP／予告／状態）に集約し、**立ち絵の上**へ。名札は常に見える＝スクロールでも隠れない。
5. 390px も**同じ構造**で、寸法だけ breakpoint で変える（アリーナ2列：左＝敵／右＝神＋OTOMO）。

## 6. Enemy HUD / Player HUD（名札）

**敵名札**（立ち絵の上・1〜2行）

```

🔥 特大 190                 攻撃力-50(2)
```

- 名前（12〜13px）／HP バー（18px・数値は 11px）／**予告 20px 以上・太字**／状態（ブロック・バフ）を**1枚のまとまり**にする

## 10. Mobile（390px）

- **同じ構造**（grid＋ドック）で寸法だけ変更。実測で 390×760／390×696／430×848 とも**全項目 100%・横スクロール 0**

## 11. 接地感（既存素材のまま）

- 背景（`backgrounds/stages/*`）は 8 枚とも**画面中央下寄りに円形の床**がある。敵・神の立ち絵の**足元をこの床の高さに合わせる**（アリーナを `align-items: end` で床ラインに揃える）
- 追加するのは CSS のみ：
  1. **接地影**：立ち絵の足元に楕円の `radial-gradient`（幅 60%・高さ 14px・黒 40%・blur）
  2. **明度**：立ち絵に `brightness(0.96)`＋背景側に弱い暗色オーバーレイで、キャラが背景より前に出る
  3. **rim-light 相当**：`drop-shadow(0 0 1px rgba(255,224,170,.55))` を 1 本足す（既存の drop-shadow に追加）
  4. **スケール**：敵 100 に対し神 0.82（現状 280:223 ≒ 0.80 を踏襲）
- 画像の描き直しは不要・禁止のまま

## 13. Phase 6-A（Combat Juice）との整合

Phase 6-A の damage number・敵リアクション・ghost HP・撃破・神の一撃はすべて**敵ポートレートとその周辺**で起きる。したがって 6-B の Acceptance に次を含める。

> **カード選択時点から着弾終了まで、敵ポートレートの 50% 以上がビューポート内かつ非遮蔽で残る**

測定方法（提案・実装済み）：`play.mjs` が「カードを選ぶ直前」「着弾（cast 280ms＋着弾 90ms 後）」「撃破」の瞬間に、遮蔽・クリップを考慮した可視率を記録する。より良い指標があれば置き換えてよいが、**遮蔽とクリップを勘定に入れること**が必須（入れないと B/C のような案を誤って合格させる）。

**読み方**：現状の「敵可視 90%台」は**スクロール 0（＝手札が1枚も見えない位置）**での値。人間は手札を触るために 531px スクロールするので、実際に着弾を見る条件では **45%**（§2）。P6 はスクロール 0 のまま手札も予告も 100% 見えており、**着弾の敵可視 52〜71%（最小 34%）**。7戦とも console error 0。

→ P6 の敵可視が下がるのは名札を上に足したぶん立ち絵が下で切れるため。**立ち絵の可変サイズ化（§5-2）で 90% 以上に戻せる**見込み（名札を下に置いたプロトタイプ P5 では 89〜98% を実測）。CSS 注入だけで両立させる P7 は破綻したため、実装で対応する。

## 18. Known Risks

1. **アリーナの高さが足りない画面**（1366×768・100% ＝ 594px）では、立ち絵が現状の 300px → 約 150px まで小さくなる。豆粒化はしないが「迫力が減った」と感じる可能性がある（1080p では 226px まで戻す clamp を提案）
2. `100dvh` はモバイルのアドレスバー伸縮で値が変わる。`dvh` 未対応環境のフォールバック（`100vh`）が必要
3. `.battle` を grid にすると、既存の `.battle-main > *` の z-index 前提や、決定77・P0② の PC 専用ブロックと衝突しうる（**既存 CSS の整理が必須**。ロールバックしやすいよう段階コミット）
4. Phase 6-A の演出（cast-flash は fixed・カットインは fixed）は grid 化の影響を受けないが、**アリーナの `overflow: hidden` が斬撃・数字をクリップしうる**（数字は立ち絵の上なので通常は問題ないが、最大クラス 52px の数字が上端で切れないか要確認）
5. ログを PC で非表示にすると、「何が起きたか」の確認手段が減る（トグルか、ミニ結果の強化で代替）
6. 託宣の効果文を省略すると初見に不親切（アイコン＋名称＋「今なら ブロック◯」は残す）
7. 自動スクロール（決定125）を無効化すると、390px の一部条件で着弾が見えなくなる可能性 → **無効化は実機確認後**に
8. 本監査はヘッドレス実測。**最終判断は CEO の実プレイ**（特に立ち絵サイズの体感と、カードの読みやすさ）
