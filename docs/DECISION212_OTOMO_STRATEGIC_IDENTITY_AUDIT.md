### 6-3. 読み

1. **OTOMO なし ≒ 現状**（被ダメ差 0.03）。現状の OTOMO は結果にも行動にも寄与していない
2. **仮想の Strategic 効果を共鳴に乗せても差は最大 −0.9 被ダメ**。発動が 0.5〜0.9 回／試合で、初回は受肉態の効果しか出ないため、**効果設計をいくら良くしても「発動位置」が価値を殺す**
3. **行動が変わるのは「共鳴を予告に合わせる」判断**（分岐 38〜46%・初分岐 R4.6）。しかしその判断は OTOMO の中身に依らない（なし＝0% は「合わせる理由が無い」ため）。＝OTOMO が「合わせる理由」を持てば行動選択は変わる、が、共鳴に縛る限り 1 試合 0.5 回しか効かない
4. 「溜めを読む」型は分岐 8% と低い：溜めのラウンド自体が機工師・道化の 2 R ずつしか無いため。**溜めの構えは魔獣・鬼将には無反応でよい（万能でない）**が、成立させるなら「溜めのラウンドに何をするか」を変える効果（攻撃 +50%）であるべきで、共鳴発動を合わせる効果ではない
5. 勝率はふつう 100%・むずかしい 99.8% で天井に張り付き、**勝率差では評価できない**（決定203 と同じ）。評価は「行動選択が変わるか」「被ダメ・盾・R・札の変化」「予告への応答回数」で行う

### 6-4. 限界

- 予告に反応する構え（§3・§5）は engine に hook が無いため、harness だけでは再現できない（本監査は「共鳴に乗せる設計では足りない」ことを示すまで）。Pilot で実装して測る
- 方策は簡易 AI（決定203 の reader）。人間の分布ではない（下限の証拠）

## 7. Progression をまだ作らない（維持）

Lv 上限・EXP・新進化・新通貨・ガチャ・収集経済・長期育成は設計しない。絆（battlesPlayed／resonanceCount／dojiReached）と形態ギャラリーは現状のまま。**構えは保存しない**（戦闘ごとに選ぶ）。Strategic Identity が Human QA で成立してから Progression へ。

## 8. UX（初見が違いを理解できる表示）

数値表を使わない。デッキ画面の絆 2 択を **構え 2 択**に置き換え、各構えを 3 行で：

```
[役割タグ]  連撃読み                 [役割タグ]  溜め読み
「連撃に強い」                       「溜めに強い」
連撃を1発ずつ受け切るたび、共鳴が1たまる    敵が溜めているラウンドは攻撃札のダメージ+50%
```

- 役割タグ（連撃読み／大技読み／溜め読み）＋「この予告に強い」＋ 1 行説明（`describeEffectList` の流儀で数値は ×10 表示）
- 敵選択画面の型ラベル（【連撃型】【トリック型】等）と**同じ語**を使い、敵 → 構えの対応が読めるようにする。決定206 の chip「予告を読む戦い」と並ぶ
- 戦闘中：構えが反応したラウンドに callout（既存 `decisionFeedback` の枠）で「連撃読み：共鳴 +1」を 1 回だけ出す（反応が見えないと選んだ意味が伝わらない）

## 9. 推奨：OTOMO Strategic Identity v0.1（1 案）

**「構え（Stance）」**：各 OTOMO に「予告の種類に反応する 1 ルール」を 2 つ持たせ、敵を見た後（デッキ画面）に 1 つ選ぶ。共鳴発動時の既存効果（守り／力）は**当面残す**が UI の主役から外す（v0.2 で構えに統合するかを Pilot 後に判断）。

| 設計原則 | 内容 |
| --- | --- |
| 反応する対象 | `EnemyIntent.kind`（multiAttack／charge）と予告量（≥ 閾値）。engine は既存の `godPassive.ts` と同じ「data-driven の hook」で実装（神 ID／OTOMO ID の if 分岐を書かない） |
| 効き方 | 「解き方が変わる」種類のみ：共鳴の加速・テンポ（draw/AP）・神技の拡張・条件付きダメージ倍率。**無条件の数値バフは禁止** |
| 万能禁止 | 各構えが反応する予告は 1〜2 種類。反応しない敵では何も起きない |
| 正解固定の禁止 | 同じ敵に 2 つ以上の構え（または神技・加護）で答えが成立する（§4） |
| 神の Identity | 上書きしない。構えは神技・共鳴効果と同方向か、神技の閾値を扱う |
| Progression | 作らない。構えは保存しない |
| 数値 | `RULES.otomoStance` に集約（不変ルール 4） |

## 11. GO / NO-GO

**GO — Narrow Pilot へ進む。** 理由：問題は「数値」ではなく「発動位置（共鳴に縛られている）」で、これは 1 OTOMO × 2 敵の最小実装で検証できる。NO-GO の条件（現構造で先に解くべき別問題）は該当しない：読みの可読性（決定206）は Production で成立済みで、Pilot はその導線（初陣 → 魔獣）にそのまま乗る。

**ただし**：Pilot は `src/core` に hook を足す（監査の範囲外）。着手は CEO の GO が必要。Progression は作らない。
