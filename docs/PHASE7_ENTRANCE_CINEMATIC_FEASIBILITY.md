## 0. Final Decision

**B. GO WITH MODIFICATIONS — Production の前に、恵比寿 1 柱で Cinematic Entrance を試作する。ただし方式は「動画」ではなく「既存の絵を動かす場面（Living Still）＋タップで入る＋同じ場面が Home になる」を第 1 段とし、動画は第 2 段の条件付きとする／Confidence：Medium**

- CEO の指摘（開いたら静止画で、没入する感じがない）は監査でも E1 の残課題として認識していた点（決定193：「音と動きは無いまま」）。E1 の情報設計は維持したまま、**入口の「動き・音・入ってくる感じ」だけ**を足す
- 修正点：①いきなり動画素材を作らない（既存キャラクターが別人になる危険と、7 柱ぶんの制作費が最大のリスク）。②毎回の長い演出にしない（セッション初回だけ・いつでもタップで即入場・続きからは 1 タップのまま）。③動画は「環境だけが動き、神は元絵のピクセルのまま」という条件でのみ第 2 段として検討する
- Medium の理由：CSS で動かす案が CEO の期待する「動画のような没入」にどこまで届くかは、試作を見て判断するしかない。性能は headless（GPU なし）の計測で、実機 iPhone の確認が要る

## 3. Audit 2 — Video Format（第 2 段で動画を使う場合の仕様）

| 項目 | 推奨 |
|---|---|
| 主形式 | **MP4（H.264・yuv420p・`+faststart`・音声トラックなし）**。全ブラウザで最も確実 |
| 副形式 | WebM（VP9）を `<source>` の先頭に置いて容量を削る（対応ブラウザだけが選ぶ）。AV1 は見送り |
| 属性 | `muted playsinline loop preload="none"`。`autoplay` は属性ではなく、Home の LCP 確定後に JS から `src` を付けて `play()`。**動画は `playing` イベントが来てから表示する**（それまでは静止画が正） |
| 低電力モード | iOS の低電力モードでは無音・インラインの動画も自動再生されず、**消せないネイティブの再生ボタンが動画の上に出る**【出典：付録 A-2】。したがって `<video>` を最初から見せてはいけない。`play()` の reject と `playing` 未到達の両方を見て、再生できた時だけ重ねる |
| poster | 既存の Hero 画像そのもの（＝ E1 の絵）。動画が来なくても見た目は E1 と同じ |
| 音声 | **動画に埋め込まない**。音つき動画は自動再生できない。BGM は既存の `<audio>`（`bgm.ts`）をタップで解錠して繋ぐ |
| 透過動画 | 使わない（VP9 alpha と HEVC alpha の二重管理になる）。神は HTML の静止画を上に重ねる |
| 解像度・容量 | 縦 720×960・4〜6 秒ループ・1.0〜1.5Mbps＝**0.6〜1.1MB／柱**【推測】 |

自動再生・コーデックの一次情報は付録 A。

## 4. Audit 3 — Duration

| 案 | 評価 |
|---|---|
| 1〜2 秒で自動的に Home | 短すぎて「世界が先」にならない。音も解錠できない |
| 2〜4 秒の固定演出 | 毎回待たせる。E1 の強み（続きから 1 クリック・約 0.4 秒）を壊す |
| 5〜8 秒の PV | 毎回は論外。初回限定でも Web では離脱要因 |
| **タップで入るループ** | **採用**。導入の動きは約 2 秒で落ち着き、その後は環境の動きが続く。**タップは 0 秒から受け付ける**（待ち時間 0）。タップが音の解錠を兼ねる |

| 場面 | 仕様 |
|---|---|
| 初回／セッション初回 | 入口の場面を出す。タップ（または Enter／Space）で Home |
| 同じセッション内で Home に戻る（Result → Home など） | **出さない**（メモリ上のフラグ。storage は使わない＝新規 key 0） |
| 再訪（別セッション） | セッション初回として出す。タップ 1 回で入る |
| 続きがある | 入口の場面の上に**「続きから」を最初から置く**。それを押せば音の解錠と再開が同時に起き、**1 タップのまま**（§11） |

## 5. Entrance Timeline（推奨仕様）

```
0.00s  黒。Hero 画像は E1 と同じ 1 枚（LCP の素材は変えない）
0.15s  場面が現れる（フェードイン 0.5 秒）。絵は入口用に拡大されている（SP：画面の高さいっぱい／PC：中央寄せ）
0.15s〜 カメラがゆっくり引く（scale 1.12 → 1.0・約 9 秒・ease-out）。粒子 2 層が漂う。光の帯がゆっくり横切る
0.60s  タップ受付開始（実際は 0 秒から受け付け、誤タップ防止に 0.3 秒だけ無視）
1.20s  ロゴ `SEVEN GODS`＋「共鳴カードバトル」がフェードイン
1.80s  「画面をタップして始める」（ゆっくり明滅）。続きがある時は金の「続きから」も同時に出る
 tap   ① BGM 解錠（入口の click の中で既存の playTrack を同期的に呼ぶ） ② 絵が E1 の位置・大きさへ戻る（0.9 秒・transform のみ）
       ③ ロゴは E1 の位置へ、UI パネルが下から 40px 上がりながらフェードイン（0.6 秒）
+0.9s  E1 Home と同一の状態。環境の動き（粒子・光・ごく僅かなカメラの呼吸）だけが控えめに続く
```

- **別の動画 → 別の Home にしない**。入口の場面と Home は**同じ DOM・同じ絵**で、レイアウトは最初から E1 の最終配置。入口の見た目は transform と opacity だけで作る【実測：§9 で最終配置が E1 と完全一致・CLS 0】
- 文言は「画面をタップして始める」。世界観語（例：「神域へ入る」）は Daily の意味と混ざるため使わない

## 6. Audit 4 — BGM Unlock

【実測：`src/components/battle/bgm.ts`】

- `playTrack('home')` は起動時に呼ばれ、自動再生が拒否されると `retryOnNextUserGesture` が **最初の `pointerdown`／`keydown` で再試行**する。つまり現在も「最初のタップで BGM が鳴る」
- ただし一次情報【出典：付録 A-4】では、**タッチ操作の `pointerdown`／`touchstart` はユーザー操作（user activation）として扱われない**。操作として数えられるのは `click`・`pointerup`（マウス以外）・`touchend`・`keydown` など。つまり既存の再試行は、スマホでは「最初のタップの `pointerdown` では鳴らず、操作が成立した後の次の `pointerdown` で鳴る」動きになりうる（実機未確認。E1 までの既知の挙動で、今回の変更範囲ではない）
- **Tap to Enter では、入口ボタンの `click` ハンドラの中で、既に export されている `playTrack('home')` を同期的に呼ぶ**（`await` や `fetch` を挟まない）。これなら `bgm.ts` は 1 行も変えずに、確実に「入った瞬間に音が鳴る」。続きからを入口で押した場合は、同じ `click` の中で戦闘の BGM へ切り替わる（既存の `playTrack('battle')`）
- 効果音（`sound.ts`・Web Audio）は、最初の効果音を鳴らす時に `ctx.resume()` を呼ぶ既存の作り【実測】。入口の `click` の後なので解錠済みになる
- iOS には着信などで起きる `interrupted` 状態があり、復帰時に再度 `resume()` が要る【出典：付録 A-4・要約のみ】。既存の BGM・効果音にも当てはまる話で、今回の範囲では扱わない（既知の注意として記録）
- 音量の立ち上がり（フェードイン）を足すなら `bgm.ts` に小さな追加が要るが、第 1 段では足さない（既存 BGM を壊さない）
- ミュート設定（ヘッダー）は既存どおり尊重する

### 8-2. 第 2 段（条件付き）：環境だけが動く動画

第 1 段の CEO QA で「まだ静止画に見える」場合のみ。

- 「元絵と別人になる動画」は **NO-GO**。判定は元絵と動画の各フレームを重ねた目視＋差分で行う

## 9. Audit 8 — Performance Budget

### 9-1. 実測（E1 preview に CSS を一時注入。headless Chromium・GPU なし）

| 計測 | 結果 |
|---|---|
| SP 390×844：カメラの引きだけ | **60fps・33ms 超のフレーム 0**（静止と同じ） |
| SP：＋粒子 2 層 | 59.5fps・33ms 超 1 |
| SP：＋光の帯（`mix-blend-mode: screen`） | 55.5fps・33ms 超 8 ＝ **blend が負荷の主因** |
| SP：CPU 4 倍・6 倍に絞っても | 55.8〜57.3fps（transform は compositor で動くため CPU 制限の影響が小さい） |
| SP：場面 → Home の移行（0.9 秒） | 55.4fps・33ms 超 1・**CLS 0・最終配置は E1 と完全一致** |
| PC 1508×660 | 静止の時点で 25〜27fps。**headless は GPU が無く、既存の全画面の星空アニメーションをソフトウェア描画しているため**で、PC の数値は実機の目安にならない。実機確認が必須 |
| 入口での絵の拡大率 | SP・DPR2 で 1.63 倍（恵比寿 1086px 版）。DPR3 では約 2.4 倍になり甘く見える可能性【推測】。暗いビネットと動きで目立ちにくいが、実機で確認する |

### 9-2. 予算

| 指標 | 予算 | 守り方 |
|---|---|---|
| LCP（SP・回線制限・中央値） | **E1 と同じ 5.9 秒前後・上限 6.7 秒** | LCP の素材は E1 と同じ 1 枚。入口の黒からのフェードは**絵の読み込み完了を待たずに始めない**（絵が LCP 要素のまま）。フェードの opacity は 0 からではなく、LCP 判定に影響しない重ね要素（黒い幕）を外す形にする |
| CLS | 0 | レイアウトを変えない（transform のみ） |
| 追加の転送量（第 1 段） | **10KB 以下**（CSS・JS） | 新規画像・動画 0 |
| 追加の転送量（第 2 段） | 動画 1 本 **≤ 1.2MB**、`preload="none"`・LCP 確定後に取得・回線が遅い時（`navigator.connection.saveData`／`effectiveType` が 2g・3g）は取得しない | poster-first・lazy video |
| フレーム | 実機 iPhone で 55fps 以上・33ms 超のフレームが移行中 3 以下 | transform／opacity のみ。`mix-blend-mode`・`filter`・`box-shadow` のアニメーション禁止。同時に動く層は 4 以下 |
| 常時の負荷 | Home に着いた後の動きは 2 層以下・タブが非表示の間は停止 | `animation-play-state`・`visibilitychange` |

## 10. Audit 9 — Accessibility / Fallback

| 条件 | 挙動 |
|---|---|
| `prefers-reduced-motion: reduce` | **入口を出さず、E1 の静止 Home を直接表示**。BGM は既存どおり最初の操作で鳴る |
| 低電力モード・動画が自動再生できない（第 2 段） | 動画の要素を**表示しない**（ネイティブの再生ボタンを出さないため）。E1 の絵のまま、CSS の動きは続く。**第 1 段（CSS のみ）はこの制約を受けない** |
| 回線が遅い・動画の読み込み失敗・非対応コーデック（第 2 段） | 動画を取りに行かない／失敗しても poster のまま。エラーは握りつぶしてゲームは進む |
| 絵の読み込み失敗 | 既存の E1 と同じ（背景色の上に UI）。入口は 2.5 秒で自動的に解除して Home を出す |
| JS エラーで入口が解除されない | **保険**：入口は CSS の初期状態ではなく JS が付ける状態にする（JS が動かなければ最初から E1）。さらに 8 秒間タップが無くても UI を操作可能にする（音は鳴らないが遊べる） |
| キーボード・スクリーンリーダー | 入口は全画面の `<button>`（「画面をタップして始める」）。Enter／Space で入る。入口の間、背後の Home は `inert` |
| 自動 QA | 既存スクリプトは Home の要素を直接探すため、入口があると実クリックが遮られる。各スクリプトの Home 到達処理に「入口があれば押す」を 1 行足す（「わかった」と同じ扱い）。6 ファイル前後 |

**入口が失敗しても、ゲーム開始を妨げない。** 最悪の場合でも見えるのは CEO QA で PASS 済みの E1 Home。

## 13. Audit 12 — Scope Decision

| 比較 | **X：E1 → Cinematic 試作 → CEO QA → Production → P3** | Y：E1 を先に Production → Cinematic は後で |

### 付録 A — 自動再生・コーデックの一次情報（Web 調査。実機確認はしていない）

| # | 事実 | 出典 |
|---|---|---|
| A-1 | iOS Safari：`<video autoplay>` は `muted` または音声トラックなしなら操作なしで再生できる。iPhone のインライン再生には `playsinline` が必須。画面上で見えている時だけ再生され、見えなくなると一時停止する。ブロックされると `play()` の Promise が `NotAllowedError` で reject される | https://webkit.org/blog/6784/new-video-policies-for-ios/ ／ https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/ ／ https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay |
| A-2 | iOS の低電力モードでは無音・インラインの動画も自動再生が抑止される（WebKit Bug 168985・RESOLVED FIXED）。`controls` が無くてもネイティブの再生ボタンが出て CSS では消せない（Bug 219889・WONTFIX「電池節約のため意図的」）。2024 年 12 月時点でも同じ報告が続く。Apple の公式ドキュメントの明文と、最新 iOS での挙動は**未確認** | https://bugs.webkit.org/show_bug.cgi?id=168985 ／ https://bugs.webkit.org/show_bug.cgi?id=219889 ／ https://developer.apple.com/forums/thread/709821 |
| A-3 | Chrome：無音の自動再生は常に許可。音つきは、そのドメインで操作済み／MEI が高い（デスクトップ）／ホーム画面に追加済み（モバイル）のいずれかで許可。操作前に作った `AudioContext` は `suspended` で始まる。Edge 固有の設定は**未確認** | https://developer.chrome.com/blog/autoplay |
| A-4 | ユーザー操作として扱われるイベントは `keydown`・`mousedown`・`pointerdown`（**マウスのみ**）・`pointerup`（マウス以外）・`touchend`。タッチの `pointerdown`・`touchstart` は対象外。操作の権限（transient activation）は時間で失効するため、`play()`／`resume()` はハンドラ内で同期的に呼ぶのが安全。iOS で同期呼び出しが必須とする Apple の明文は**未確認**。iOS の `interrupted` 状態は要約のみ確認 | https://developer.mozilla.org/en-US/docs/Web/Security/User_activation ／ https://developer.mozilla.org/en-US/docs/Glossary/Transient_activation ／ https://github.com/WebAudio/web-audio-api/issues/2585 |
| A-5 | WebM（VP8／VP9）は macOS Safari 14.1 から、iOS／iPadOS は 17.4 から。AV1 は Safari 17.0 以降でハードウェアデコーダ搭載機のみ。**H.264 MP4 が最も安全**。透過動画は Safari が HEVC with alpha、Chrome／Firefox が VP9 alpha で、単一形式では成立しない | https://webkit.org/blog/15063/webkit-features-in-safari-17-4/ ／ https://webkit.org/blog/14445/webkit-features-in-safari-17-0/ ／ https://jakearchibald.com/2024/video-with-transparency/ |
| A-6 | Chrome では `<video>` も LCP 候補で、poster の読み込み時刻と最初のフレームの表示時刻の早いほうが使われる。LCP 要素の動画に `loading="lazy"` は使わない。自動再生しない動画は `preload="none"`＋poster。`src` を後から付ける方法の明文の推奨は**未確認** | https://web.dev/articles/lcp ／ https://web.dev/articles/lazy-loading-video |
| A-7 | `prefers-reduced-motion` は検出用のメディア特性で、動画の自動再生を止める効果は持たない。サイト側で対応する | https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion |

実装上の結論：①静止画を正とし、動画は「再生できたら重ねる」追加演出。②音は入口の `click` の中で同期的に鳴らす。③LCP は静止画の `<img>` に担わせる。④reduced motion と低電力モードは静止画のまま。⑤透過動画は使わない。
