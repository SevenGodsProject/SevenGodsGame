## 0. 総合結論

**GO（条件付き）。Production 前に入れる Visual Patch は 1 テーマ＝「神の一撃の専用舞台化」だけ。** 他は Post-Release。

厳しく判定した根拠は次の 3 点（詳細 §19）。

1. **実画面モック比較**で、既存素材＋CSS だけの候補 2 つを同じ条件で並べた結果、「神の一撃の専用舞台化」は 1 枚で商用の必殺演出に見える差が出たが、「立ち絵の接地＋色調グレーディング」は **差が小さい**（立ち絵がアリーナ幅の 16〜19% しかなく、背景が暗く情報量が多いため、接地影・床光・リムが埋もれる）。後者を効かせるには立ち絵の拡大か再描画（分類 B）が要り、CSS だけでは「浮いて見える」問題を解消しきれない
2. **回帰リスク**：神の一撃は `position:fixed` の overlay（`.resonance-cutin`）で、6-A のタイムライン（暗転 0.2s → スライド 0.4s → 0.9s で `.burst-banner` へ）と `onAnimationEnd` の受け渡しを **そのまま**残して中身だけ差し替えられる。6-B の一画面性・6-C の callout／振り返りには触れない。接地・グレーディングは立ち絵と HUD の間に層を挟むため、6-A の反応・崩れ落ちと SP 性能に検証が要る
3. **費用**：神の一撃は約 1 日（実装 0.5＋QA 0.5）。神選択の儀式化・World UI・Typography は JSX 変更や全画面 CSS に及び、いずれも 1.5〜2.5 日で、Release Hygiene・Release Audit の前に置く価値と釣り合わない

**NO-GO とした候補**：神選択の儀式化（効果は大きいが JSX 再構成で Tutorial 導線・SP 縦積みに回帰リスク）、World UI 一括（明朝化は 6-B のレイアウト計測を変える）、接地・色調（CSS だけでは弱い）、勝利の余韻（効果中・費用低だが「1 テーマ」の原則で外す。Post-Release の最初の候補）。

## 1. 月蝕綺譚の画面品質の強み（一次情報から観察した事実）

公式サイトの画面 6 枚と必殺画像から確認した事実（推測は「（推）」）。

1. **色**：全画面の地色が黒に近い藍。金は見出し・数値・選択枠・主ボタンにだけ使い、面では使わない。橙／赤は HP バーと「今週の五行」バッジなど「状態」にだけ使う。**同一画面に彩度の高い色を 3 つ以上置かない**
2. **枠**：カード・パネル・タブはすべて **1px ヘアライン＋角丸 6〜10px＋塗り黒 60〜80%**。主ボタンだけが二重線＋四隅の飾り。飾りは 1 画面 1 か所
3. **文字**：見出しは明朝・大・字間 0.3em 以上。副題を小さく添える。数値のみサンセリフ。縦書きは要所だけ
4. **キャラの置き方**：編成は立ち絵（腰上）を右 60% に置き、左にステータス、下に半透明の編成列。立ち絵の背後に暖色のグロー（推）。召喚は横たわる立ち絵の上に墨帯を斜めに乗せる＝**UI がキャラを避けるのではなく、キャラの上に UI が置かれる**
5. **必殺**：傾いたパネル（約 -6°）＋放射状の集中線＋満月＋技名を金の明朝で画面幅いっぱい。必殺画像 3 段は **同じポーズにエフェクト量だけを足している**（素材差分は小さい）
6. **1 画面 1 主役**：浄夜は「討伐位」だけを大きく、他は細い進捗バー。闘合いは演目カード 1 枚＋ボタン 1 つ
7. **記号の反復**：三日月・月蝕・鳥居・灯籠・瑞雲・墨を、ロゴ／タブ／背景／ボタン飾りに反復
8. **語り手**：マスコットが吹き出しで 1 行。説明文をパネルに書かない

## 3. CEO 優先確認 8 項目への回答

### 3-1. God Strike — 「専用舞台」に近づける余地
**余地は大きく、既存素材＋CSS だけで届く。** モック（§18、`pc-oni-2-mockA-godstrike.png`／`sp-oni-2-mockA-godstrike.png`）で確認した構成：暗転の上に集中線（`repeating-conic-gradient`）、-5° の黒帯（金ヘアライン上下）、帯の中に **円形マスクの keyvisual**（既存 675×900）＋「◯◯、共鳴発動」小＋「神の一撃」を金グラデの明朝・字間 0.18em で大（SP は縦書き）。**6-A のタイムラインは不変**（0.2s 暗転／0.4s スライド／0.9s 解除）。神ごとの差は `OTOMO_THEME_COLOR[godId].base`（`godStyle.ts` 既存 7 色）を帯のヘアラインと集中線に使う。技名データは存在しないので「神の一撃」固定＋神名（新規文言なし）。
月蝕綺譚と同じにしない点：帯を墨の刷毛にしない（直線の黒帯）、満月を置かない、集中線は細く薄く（opacity .18）、円形マスク＝SEVEN GODS の記号。

### 3-2. Battle — 1 つの世界に見えるか
**見えていない。原因は「浮き」「汎用パネル」「色温度の不一致」の 3 つ。** ただしモック B（接地影・床光・リム・accent 乗算＋周辺減光）を注入した実画面（`pc-oni-1-mockB-grounding.png` 等）では、**周辺減光で額縁感は出るが、立ち絵の接地は判別しにくい**（立ち絵が小さく、背景が暗く密度が高いため）。CSS だけで「1 つの世界」に達するには立ち絵のスケール変更（6-B の一画面性と競合）か再描画（B）が要る → Post-Release。

### 3-3. 神選択 — 儀式にできるか
**できるが JSX 再構成が必要。** フォーカス中の神の keyvisual を右 55% に大きく、左にステータス、下に 7 神サムネ列（月蝕綺譚の編成の階層原理のみ。配置比率・装飾は独自）。SP は上 45% keyvisual（既存 `KEYVISUAL_OBJECT_POSITION`）＋下ステータス＋横スクロールサムネ。効果は大きいが、Tutorial 導線（「新しく始める」分岐）・SP 縦積み・既存テストに回帰リスクがあり、**Production 前には入れない**。

### 3-4. Victory — 帳票感が残っていないか
**残っている。** 6-C の振り返りで「勝因」は出るようになったが、構造は「タイトル → 副題 → 振り返り → 神 110px → スコア → 内訳表 → ボタン」の縦リストで、背景は暗転した戦場のまま。神の keyvisual を背後に大きく（opacity .35・下端フェード）、上端に金の光条、「勝利」を明朝 40px・字間 0.4em にするだけで帳票感は薄れる（CSS＋子要素 1 つ、6-C の順序・報酬導線は不変）。**効果中・費用低・リスク低**だが、1 テーマ原則で Post-Release の第 1 候補。

### 3-5. Character Grounding — 既存素材＋CSS でどこまで
**「少し」まで。** モック B の実測所見：(a) 接地影（楕円・黒 70%・blur 2px）は戦火の陣・月牙の霊峰とも背景の暗部に溶けて視認しにくい、(b) 床光（accent・screen）はうっすら効く、(c) リム（`drop-shadow` accent 5px）は敵のドット縁を強調して逆効果になりうる、(d) accent 乗算 12% は画面全体が沈み、数字・callout のコントラストが下がる。**効かせるには立ち絵を 1.3〜1.5 倍にする必要**があるが、6-B で確定した一画面レイアウト（PC アリーナ高 326px）では不可。結論：CSS だけでは改善幅が小さく、Production 前の patch にしない。

### 3-6. World UI — Web UI 感の残り
| 要素 | 現状 | Web 感 | 直し方（CSS のみ） |
|---|---|---|---|
| HP バー | 角丸 999px・`#16203c` 地・幅 transition | 中 | 角丸 3px・両端に 1px 金の留め・地を黒 70% |
| Intent（予告） | 13px 文字＋tier 別の outline／glow | 低〜中（6-B で改善済み） | 札型の小枠に |
| Resonance | 角丸 999px バー＋label 10px | 中 | 7 目盛の刻み（`repeating-linear-gradient`）を入れて「七」を見せる |
| Divination（託宣） | 紫枠 8px 矩形ボタン×3 | **高** | 黒 72%＋金 22% ヘアライン、アイコンは既存絵文字のまま |
| AP（神力） | 文字＋細バー | 中 | 数字を明朝・大、バーを刻みに |
| パネル全般 | 白 10% 枠・14px・blur 10 | **高** | 金 22% ヘアライン・8px・二重線・blur 6 |

一括で直すと **6-B のレイアウト計測（フォントメトリクス・高さ）を再検証**する必要があり、Production 前は見送り。

### 3-7. Color Grading — 別々に生成された画像に見える箇所
1. **戦火の陣（赤）× 鬼将（紫）× 大耀（緑迷彩）**：3 色相が衝突。最も目立つ
2. **蒼海の宮／月牙の霊峰（青）× 恵比寿・福永（暖色）**
3. **OTOMO 320 版**：キラキラが焼き込まれ、暗いステージで縁が白く浮く
4. **敵ドット風 vs 神線画**：質感の差（グレーディングでは埋まらない。B）
5. 神選択・敵選択のサムネ：それぞれ別の光源・彩度（クロップ基準の統一で緩和）

`--stage-accent` は注入済みで未使用。乗算 8〜12% で 1・2 は緩和するが、モックでは画面全体が沈むため **HUD と数字の下・立ち絵の上**に限定する設計が要る（Post-Release）。

### 3-8. Transition — 1 つの世界の進行に見えるか
**見えない。** Home→神→難易度→敵→デッキは即時切替（Web ページ遷移そのもの）。デッキ→戦闘の Boss Entrance（1.5s）と戦闘→結果（崩れ落ち→結果）だけが「進行」に見える。0.22s のフェード＋上 6px スライドを `GameFlow` の画面切替に 1 クラス足すだけで揃う（reduced-motion で無効）。効果は中、費用 0.25 日、リスク低。1 テーマ原則で Post-Release（勝利の余韻と同時に入れるのが自然）。
